# 报告页「学员原话 × 模型建议」对比 · 设计方案

> 背景：同事提出「在训练评分报告界面加上学员实际回答与模型生成答案的对比」。
> 结论先说：**这个数据已经有了、报告页也已经在展示**。真正缺的不是功能，是**展示形态**。

---

## 一、现状：功能已存在，只是不好用

### 数据侧（齐全，不用新建）

评分模型（裁判）每轮都会产出三样东西，且已经落库在 `evaluations.report`：

| 字段 | 内容 | 提示词里的硬要求 |
|---|---|---|
| `roundComments[].userMessage` | **学员当时的原话**（逐字引用）| 必须逐轮覆盖每一轮客服发言，不能遗漏或重复 |
| `roundComments[].comment` | 该轮点评 | ≤60 字 |
| `roundComments[].recommendedRewrite` | **模型给的更优表达** | 必须是客服能**直接说出口的完整话术原句**，带称谓、句子完整；禁止写成「先安抚再追问」这类要点提纲 |

违规项同理：`violations[].originalQuote`（原话）+ `reason`（原因）+ `recommendedRewrite`（建议改写）。

> 关键点：`recommendedRewrite` 的质量是被提示词强约束过的——**不是"建议方向"而是可直接照说的整句**。这正是能做"对比"的前提。

### 展示侧（已上线，但形态有问题）

`pages/result`（训练报告）已有两个相关区块：

**① 关键轮次点评**（现状形态）
```
第 3 轮
"（学员原话）"
（评委点评，60 字以内）
更优表达：（模型改写）
```

**② 严重违规**
```
违规类型                          -30分
"（学员原话）"
（违规原因）
建议改写：（模型改写）
```

`pages/mistakes`（错题本）也有「建议改写」框，`pages/mistake-retrain` 支持一键复制。

### 所以同事感受到的真实痛点是什么

我判断是下面四条中的一条或几条：

1. **原话和改写「上下堆叠、中间夹点评」** —— 想对照得来回扫，不在同一视线内，`对比感`很弱
2. **默认只展示第 1 轮** —— 折叠逻辑是 `expanded ? 全部 : 只取第 1 条`，多轮训练时后面几轮被藏起来，容易让人以为「只有一条」
3. **没说清「差在哪」** —— 只并列了两句话，学员要自己悟出「我少了称谓 / 我跳过了需求挖掘」
4. **两个区块重复** —— 同一轮如果既有违规又有点评，会在「违规区」和「轮次点评区」各出现一次，读起来像重复内容

---

## 二、五个方案与权衡

### 方案 A｜并列对照卡（推荐先做）

把「上下堆叠」改成**两栏紧邻对照**，并补一句"差在哪"。

```
┌ 第 3 轮 ─────────────────────────────┐
│ 你当时说的            建议这样说        │
│ "（学员原话）"        "（模型改写整句）" │
│                                      │
│ 差在哪：缺少称谓；直接报价，未先问清诉求 │
└──────────────────────────────────────┘
```

- **改动**：`pages/result/result.wxml` + `wxss`；后端在 `roundComments` 里补一个 `diffHint` 字段
- **成本**：低（前端为主）
- **收益**：直击痛点 1，对比一眼可见
- **风险**：375px 窄屏左右两栏会挤 → **建议改为上下两栏 + 左侧色条区分**（"你说的"灰底 / "建议"蓝底），比强行左右分栏稳
- **注意**：`diffHint` 若让模型生成，会增加一次输出长度；也可以先**不由模型生成**，改用纯前端拼接（见方案 C）

### 方案 B｜差异高亮（教学价值最高，成本也最高）

在方案 A 基础上做**词句级标注**：学员原话里缺失/踩线的部分标出来，改写里新增的正确动作标出来。

```
你当时说的：        "您好，这个种植牙是 8900。"
                              ~~~~~~~~  ← 未先了解情况，直接报价
建议这样说：        "王先生，我能先了解下您缺牙多久了吗？……"
                    ~~~~~~~~~~~~~~~~~~~~~~~~~~  ← 先建立需求再谈费用
```

- **改动**：需要新增一次模型调用（对比分析），或做规则化提取（如"是否含称谓""是否含提问句"）
- **成本**：高。模型做差异标注**有幻觉风险**（可能标错、编出不存在的差异）
- **收益**：教学价值最高——学员不用自己悟
- **建议**：**先做 A，观察学员反馈和 `diffHint` 质量后再决定是否上 B**。若要上，优先只做 2–3 类**可规则判定**的差异（称谓 / 是否提问 / 是否含绝对化词），不要交给模型自由发挥

### 方案 C｜可见性与去重修复（成本最低，可能直接解决问题）

纯前端改动，解决痛点 2、4：

1. **默认展开全部轮次**（或至少前 3 轮），而不是只显示第 1 条；折叠按钮改成「收起」而不是「展开」
2. **合并重复**：把「违规区」的建议改写与「轮次点评区」的同轮内容合并——违规轮次只在违规区出现，不再在点评区重复
3. 增加一个「只看有问题的轮次」筛选（学员真正想复盘的是这几轮）

- **成本**：极低（只改前端）
- **收益**：如果同事的抱怨本质是"我没看到"或"看起来像重复的"，这一条就能解决
- **建议**：**和方案 A 一起做**，两者叠加才是完整形态

### 方案 D｜与「AI 客服示范」打通（整场对比）——不推荐

看起来最诱人：把学员这一通训练，和 AI 客服示范的那一通并排对比。**但我建议不做**，理由有三条：

1. **角色是反的**。`roleplay` 那套是**学员扮演患者、AI 扮演客服**（页面文案：「患者模拟完成」「本复盘用于帮助新人理解标准客服的沟通结构」），跟"学员扮客服"的训练不是同一个视角，直接并列会产生误读。
2. **它刻意没有分数**。`roleplay-result` 明确写着「不含数值评分」，是"理解结构与边界"的学习材料，不是可比较的答卷。
3. **模型依赖未就绪**。示范那条线计划接入微调模型，目前基础模型效果存疑；把它绑进评分报告会把两个成熟度不同的功能耦合在一起。

> 更实际的替代：现有 `recommendedRewrite` **本身就是"标准客服会怎么说"**。把它的展示做好（方案 A/B），比拉一整通示范过来更划算。

### 方案 E｜把对比结果变成可带走的资产（小增强，顺手做）

报告页每条改写旁边加：
- **一键复制**（`pages/mistake-retrain` 已有这个能力，搬到报告页即可）
- **收藏进话术锦囊**（`learner_phrase_favorites`）——注意项目里「可收录话术」**没有"收录"这个动作**，报告 ready 后自动进锦囊，学员真正的动作是**收藏**

- **成本**：低
- **收益**：对比完能立刻留下、下次能翻出来用

## 三、推荐组合与落地顺序

| 顺序 | 做什么 | 成本 | 解决什么 |
|---|---|---|---|
| **第 1 步** | **方案 C**（展开策略 + 去重）+ **方案 A**（两栏对照） | 低 | 痛点 1、2、4 一起解决 |
| 第 2 步 | 方案 E（复制 + 收藏） | 低 | 对比完能带走 |
| 第 3 步 | 方案 B（差异高亮，**只做可规则判定的 2–3 类**） | 中高 | 痛点 3 |
| 不做 | 方案 D（整场示范对比） | — | 语义不匹配 |

**一句话建议**：先花很小的成本把**现有对比"摆正"**（并列 + 默认展开 + 去重），再决定要不要让模型解释"差在哪"。第 1 步做完就应该请同事再看一次——很可能他的诉求就已经满足了。

---

## 四、落地方案 A 时的两个技术约束（提前避坑）

1. **WXML 不能对数据路径调用函数**（依赖追踪失效且不报错）。所以"是否展开""每轮显示什么"这类派生值，必须在 JS 里预算成字段再 `setData`，不能在模板里写 `list.slice(0, 3)`。现有 `foldList()` 就是这个原因。
2. **窄屏优先用上下两栏而不是左右分栏**。375px 宽下左右各 160px 放不下 20–100 字的话术整句，会被迫折行成"两个细长条"，比现在的堆叠更难读。上下两栏 + 色条区分（灰底=你说的 / 蓝底=建议）在小屏上更稳。

---

## 五、需要确认的一件事

同事说的「模型生成答案」，**指的是下面哪一种**？这决定做 A 还是 D：

- **(a) 逐句改写建议**（`recommendedRewrite`）→ 已经有了，做方案 A/C 优化形态即可 ← **我按这个是主流理解**
- **(b) 一整通 AI 客服示范**（`roleplay`）→ 属于方案 D，涉及角色反转与模型依赖，建议先不开

如果同事的实际场景是"学员说错了，想看看**标准客服是怎么接这句话的**"，那 **(a) 就够了**，而且现成的数据质量足够支撑。
