## 三、改动清单（按主题）

### 1. 达标判定可解释化（P0-1）

- 新增 `planScoreBasis()`，主管列表 / 计划详情 / CSV 导出 / 学员端**四处统一下发** `scoreBasis`（`dimension` / `total`）
- 计划详情补 `focusDimension` / `focusDimensionLabel`——此前详情接口不下发维度，主管页面无法说明判定依据
- 前端：`admin-training-plan-detail` 每行显示判定依据（回退时写明「已按综合均分 X 分判定」）；`training-plan-detail` 的 `scoreName` / `scoreLabel` / `scoreHint` 改为维度感知
- 涉及：`backend/src/reliable_store.h`、`pages/admin-training-plan-detail/*`、`pages/training-plan-detail/*`、`utils/supervisor.js`

### 2. 计划口径与防刷分（P0-2）

- 迁移 `023`：`training_plans.max_per_scenario SMALLINT NOT NULL DEFAULT 0`（具名 CHECK 0..10，0=不限）
- `planProgressJoin()` 加 `ROW_NUMBER() OVER (PARTITION BY scenario_id ORDER BY finished_at)` **截取最早 N 次**（放在内层子查询，避免「次数按上限算、均分按全部算」错位）
- 选「给同场景计入次数封顶」而非「强制主管指定场景」：约束更轻，不剥夺学员自主路径
- 前端建计划页表单顺序改为「名称 → 周期 → 目标维度 → 最低次数 → 达标线 → 同场景上限 → 说明 → 截止」，**场景范围降级为可折叠高级约束**
- CSV 列重排为「目标维度 / 判定分 / 要求分 / 判定依据 / 同场景次数上限 / 综合均分 / 是否达标」
- 顺带修掉一个既有缺陷：`utils/plan.js` 的 `scoreDone` 原用 `avgScore` 算，指定维度时会给出与后端相反的结论

### 3. 场景 ↔ 维度映射（P0-3）

- 迁移 `024`：`scenarios.dimension_weights JSONB NOT NULL DEFAULT '{}'` + 具名 CHECK（必须是 object）
- 回填 **10 条**上架场景（各场景权重和 = 1.0）；模板与下线场景保持 `{}`
- 后端新增 `normalizedDimensionWeights()`（白名单 + 归一化）与 `dimensionFocusOf()`（渲染成降序数组）
- **刻意偏离计划**：计划写「前端加一份五维 key↔中文名映射」，实际改为**后端下发中文名**——项目里中文名副本已有 5 处，再加就是第 6 个
- 语义要点：`{}` = 未标注，与「权重为 0 = 不练」是两种意思，推荐逻辑必须跳过 `{}`

### 4. 弱项 → 一键复练（P0-4）

- 新增 `GET /api/learning/retrain-candidates?dimension=`（learner_only）：只返回该维度权重 > 0 的场景，按权重降序，附 `completedCount` / `avgDimensionScore` / `activeSession`
- **排序刻意不看学员历史分**：掺入历史分会让同一份弱项对不同学员给出不同顺序，无法解释；「这个场景练这个维度」是场景自身属性
- 新增页面 `pages/retrain-candidates`（比重百分位 + 已练次数 + 该维度均分 + 动作按钮）
- `pages/profile` 弱项卡片新增复练入口——**此前这项能力是死胡同**（后端算出弱项却没有任何入口可跳）
- 抓到并修掉：`utils/plan.js` 的 `normalizePlan` 是显式构造返回对象的，不含 `focusDimension` → 按维度筛计划永远筛不到，横幅会静默不显示

### 5. 场景设计规范化 + 骨架模板（P0-5）

- 新增 `docs/训练场景设计规范.md`：**六条质量判据** + 反例 + 主管自查清单
- 迁移 `025`：8 条骨架模板（4 分类 × basic/advanced），`is_template=TRUE` + `is_active=FALSE`，id 前缀 `tpl-`，`sort_order` 占 9xx 保留区
- 后端 `scenarioQualityWarnings()`：8 条机器可判的软校验（`HIDDEN_COUNT` / `OPENING_IS_QUESTION` / `NO_RELIEF_CONDITION` / `NO_ESCALATION_CONDITION` / `NO_EVASION_RULE` / `NO_SERVICE_GUIDANCE` / `NO_RED_LINE` / `PLACEHOLDER_NOT_REPLACED`）——**只提醒不拦截**
- `createScenario` 支持 `fromTemplateId` 克隆；`supervisorScenarioCatalog` 新增 `templates` 段
- 新增页面 `pages/scenario-templates`（按分类分组，独立成页而非折叠区）
- **同时把 `roleplay_config` 暴露进编辑表单**——此前主管自建场景的 `suggestedQuestions` / `serviceGuidance` 恒为空
- 抓到 2 个真 bug：模板基底漏继承 `summary`；`--noproxy *` 被 shell 当通配符展开导致脚本像卡死

### 6. 难度档位（P1-1）

- 迁移 `026`：`scenarios.difficulty_tiers JSONB`（只存**非默认档**）+ `sessions.difficulty_tier TEXT`（CHECK standard/advanced）
- 迁移 `027`：给 11 条业务场景的进阶档各回填 **2 句开场白**——修复「状态更紧张、台词照旧」的`参数变了体感没变`问题
- 后端：`applyTierToHidden()` / `pickTierOpening()`；开场白按**会话 id 的 FNV-1a 哈希**确定性选取（同一会话永远同一条）
- **D1 硬口径**：`planProgressJoin()` 加 `AND s.difficulty_tier = 'standard'`——进阶档不进计划达标（否则「勇于挑战」会变成「拖累主管给的计划」）
- 安全修正：`listScenarios` 原本透传整个 `difficulty_tiers`，加了 `openings` 后会把**患者全部台词**下发给学员端 → 新增 `tierSummaryForLearner()` 只下发 `summary`
- 主管端四处呈现：成员均分拆两档 / 进阶挑战率 / 趋势按档位 / 场景管理页可编辑档位参数

### 7. 复练变体池（P1-2）

- `hidden_config.variants`（可选数组，每组部分覆盖 `hidden` / `instructions`），**零 schema 迁移**
- `applyVariantsToHidden()` 按 `session_id` 确定性选组；返回值**一律剥离 `variants` 键**（否则会把其他变体的顾虑泄进患者提示词 = 看到答案）
- 迁移 `028`（2 条示范）→ `029`（**铺到全部 10 条上架场景**）
- 新增「有没有变体池」的三个出口：软校验 `NO_VARIANT_POOL` + 目录下发 `hasVariantPool` + 列表橙色标记「未加变体池」
- 主管端新增**复练变体池编辑器**（≤5 组，逐条增删顾虑 + 可选披露节奏）
- 修复一个静默数据丢失：主管编辑场景任何字段都会**清空变体池**（`validateScenarioPayload` 白名单重建时丢掉 `variants`）

### 8. AI 场景骨架生成（P1-3）

- **先还债**：队列的「不是 A 就是 B」隐式分支改成两张**显式映射表**（`AiJobKind` / `GenerationTarget`），未知类型**拒绝执行**
- 迁移 `030`：`knowledge_admin_jobs.kind` 放开 `scenario_draft`；`scenarios` 加 `generation_id`（生成中标记 + 乐观并发闸门）与 `ai_draft`（**永久来源标记**）+ 兜底 CHECK
- 落库走 `main.cpp` **注入回调**（`setScenarioDraftWriter`）——`knowledge` 层不认识 `scenarios` 表，且 `reliable_store.h` 单独 include 编不过
- 模型提示词把六条质量判据写进去，并**禁止填服务要点**（机构红线必须主管填），落库前再校验一次
- 前端：主管端「AI 生成骨架」入口 → 需求表单 → 轮询 → 成功后直接进编辑器补红线
- **抓到真 bug**：`applyScenarioDraft` 的 SQL 从 `$4` 起编号而实参从 `$3` 起 → PG 报「无法确定参数类型」→ 任务永远进不了 `succeeded`（编译、HTTP 提交、占位行创建全都正常）

### 9. 逐次达标闸门（P2-2，替代原「最后一次」）

- 迁移 `031`：`training_plans.require_each_pass BOOLEAN NOT NULL DEFAULT FALSE`（**默认关闭 = 存量语义一字不变**）
- `planProgressJoin()` 新增 `min_score` / `min_focus_score` / `last_score` 聚合；新增 `planJudgeScore()` 取代 `planScoreFor()`
- **四路判定同步**：主管列表（SQL `CASE WHEN`）/ 计划详情 / CSV 导出 / 学员端；`createTrainingPlan` 与 `publishPlan`（含 overrides）持久化
- 前端：建计划表单加开关（含编辑回填）+ 判定依据文案跟随切换（**7 文件 15 处**）
- 决策依据（真实数据）：`75 + 52` → 均分 63.5 **过线**、最低分 52 **不过**；`91/0/5/79` → 最后一次 79 **过线**（证明「看最后一次」会放松标准）
- **E2E 抓到真 bug**：上一轮新增的三处学员级响应字段缺少对应 SELECT 列 → pqxx 抛异常 → 计划详情与学员端列表 500（编译、ctest、自写 SQL 全都发现不了）

- 构建环境修复：依赖从 `%TEMP%` 搬到 `C:/Users/Zhangjie/dev-deps/oral_training/` + shim（`build-offline.sh` 一键，无需网络）
- `start-backend.cmd`：启动失败时**自动诊断重跑并落盘** `start-backend-server.log`
- 迁移清单补齐：`026`/`029`/`030`/`031` 的历史遗漏（`README.md` ×2、`backend/README.md`、`docs/setup.md`、`portable/README.txt` ×3、`migration_reliability.ps1`）
