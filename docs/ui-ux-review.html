UI/UX 审查报告

口腔客服 AI 陪练小程序 · 设计诊断与改版建议

基于 ui-ux-pro-max 设计智能对全部 13 个页面 + 自定义 TabBar 的逐页审查。目标风格:简洁克制、学员可直达训练、无"AI 味"。

审查范围:13 页面 · 4 Tab 风格方向:极简瑞士风 / 专业克制 生成时间:2026-08-30
1总诊断:为什么会有"AI 味"

一句话结论

问题不在功能,而在视觉语言过于"热闹":高饱和靛蓝大色块、浅紫底铺满全站、彩色标签与彩条装饰过多、信息密度过载。学员进来第一眼看到的是"设计",而不是"训练入口"。

四个核心来源

1
配色是最大的"AI 味"来源。品牌色 #5B6EF5 是典型的高饱和靛蓝(偏紫),配合 #EEF0FF 浅紫底在首页概览卡、对话页头部、结果页 hero、模式切换、各类标签中大面积使用——这正是当下 AI 产品模板的"标准紫",辨识度反而最低。
2
装饰性元素堆叠。卡片顶部彩色横条(::before)、双色渐变、胶囊标签、多重阴影同时出现,视觉噪声大。同一屏最多同时出现 4-5 种彩色(蓝/橙/绿/红/灰)。
3
信息密度过载。首页 6 个模块、结果页 12 个区块、训练场景页三层嵌套卡片,一屏塞进过多内容。学员需要"扫视"而非"直接看到"重点。
4
文字层级太单薄。全局只有 32/26/22 三档字号,页面标题与卡片标题几乎同号;22rpx(≈11px)还被用作正文,对比度不足,读起来吃力。
2全局基础(app.wxss / app.json / TabBar)
全局已有不错的设计 token 雏形,但存在几个影响全局观感的问题。

发现的问题

!
导航栏整块品牌蓝(navigationBarBackgroundColor: #5B6EF5),每个 tab 页顶部都是大蓝条,是"AI 味"的第一印象来源。
!
主色饱和度过高,且页面多处硬编码 #5B6EF5 / #EEF0FF 而不是引用 CSS 变量,后续换色成本高。
!
字号体系只有三档,且 26rpx 同时充当正文和次级文字,层级区分不足;22rpx 被用于大量正文(如首页场景描述、最近训练时间),偏小。
!
状态色使用较克制(值得肯定),但标签的彩色底(浅绿/浅橙/浅红底 + 彩色文字)在列表中密集出现时仍是噪声。
!
TabBar 选中色为品牌蓝,与全局"紫"绑定;图标用 PNG,选中态仅换色。

建议

换主色为专业深海军蓝 #1F3864,CTA 用克制蓝 #2F6FED;导航栏改纯白底 + 深色文字(navigationBarTextStyle: "black"),页面内用浅蓝灰 #EEF2F8 代替 #EEF0FF。整体从"紫调"转向"蓝灰调",立即去掉一半 AI 味。
字号扩为五档:40rpx 页面大标题 / 32rpx 卡片标题 / 28rpx 正文 / 24rpx 辅助 / 22rpx 注脚。正文不再用 26rpx 以下,22rpx 只做时间、提示等弱信息。
全站消灭硬编码色,所有 #5B6EF5 换成 var(--color-primary),统一走 token。
3逐页审查(13 页 + TabBar)

TabBar(首页 / 训练 / 数据 / 我的)

!
4 个 Tab 均正常,但"数据"Tab 对学员展示的是个人数据、对主管展示机构数据,同一 Tab 双角色语义在视觉上未做区分。
!
选中态图标仅换 PNG 颜色,选中/未选对比偏弱。
建议:TabBar 底色纯白 + 顶部细边框(已接近),选中色改新主色;图标可在后续统一替换为线性图标。

home · 首页 AI 味最重

!
数据概览卡是整块高饱和蓝(background: var(--color-primary) + 蓝阴影),一进首页第一眼就是大蓝块。
!
页面 6 个模块叠放:品牌问候、搜索、概览卡、推荐场景、最近训练、热门话术轮播,首屏信息过载,学员不知道先做什么。
!
热门话术 swiper 自动轮播(autoplay 4 秒),内容自己滚动,干扰阅读,是典型"为了动效而动效"。
!
推荐场景卡顶部有彩色横条 + 彩色难度标签 + "去训练"链接,一张卡 3 个彩色元素。

建议

概览卡改白底:去掉整块蓝,改为白卡片 + 1rpx 边框 + 极浅阴影,数据用大号深色数字(40rpx)做主视觉,状态色只用于达标/待提升。首页降密度:首屏只留 品牌问候 + 搜索 + 概览卡 + 推荐场景(2×2),"最近训练"和"热门话术"折叠为"更多"入口或次级区块。去掉自动轮播:改为静态 2 条精选 + "查看全部",或保留滑动但由学员手动切换。

index · 训练场景选择 三层嵌套

!
卡片套卡片套面板:分类卡(可折叠)→ 情景卡 → 患者画像输入面板,三层嵌套,展开后一屏高度失控。
!
每张情景卡同时出现:序号、难度胶囊、进行中标记、名称、描述、及格分、历史最佳、患者画像行、画像编辑按钮、训练按钮、重新开始链接——单卡信息过载。
!
"患者画像(必填)"打断训练动线:学员想练,却被要求先填三行表单(年龄/描述/情绪),这是转化率最大的摩擦点。
!
模式切换滑块 + 边界提示条(浅紫底)又加一层紫色。

建议

拉平层级:分类卡只做入口,点击后进入单一"场景列表"页(列表行式:名称 + 难度 + 历史最佳 + 训练按钮),去掉三层嵌套。画像后置:把"必填画像"改成开始训练后的第一轮引导(在对话页顶部一次性填写),或提供"默认画像"一键使用,不阻塞开始按钮。信息减负:卡片默认只显示 名称 + 难度 + 得分,其余(及格分、画像)收进"详情"。

✓
头部已改白:白底 + 深色文字 + 细边框,轮次计数器为浅蓝灰胶囊,不抢对话注意力。
✓
辅助面板默认收起:训练辅助只留一行标题(展开 ▾),点击展开快捷话术与历史提示,对话区可视范围更大。
✓

✓

roleplay · 患者模拟对话页

!
与 training 同构,同样的问题:头部大蓝块 + 辅助面板(建议提示)常驻。
!
"标准客服"消息下方跟随学习要点卡片 + 合规边界,信息块较大,会打断"我(患者)提问 → 客服回答"的对话流。
!
按钮文案"提问"(学员扮演患者)与 training 的"发送"不一致,但视觉完全一样,容易混淆两种模式。

建议

学习要点折叠:默认只显示"客服答复",学习要点收进"学习要点 ▾"展开;或用分隔卡片与对话气泡在视觉上明显分离(灰底 + 左侧细线)。模式可辨识:患者模拟页头部加一个轻量徽标"患者模拟",让学员知道此刻自己扮演患者。

result · 训练结果页 12 区块

!
整页 12 个信息区块:hero(蓝底+分数环)、免责、五维、综合评价、两条反馈卡、严重违规、关键轮次、可收录话术、4 个按钮、2 个链接——学员看完要滚很久。
!
hero 又是整块蓝 + conic-gradient 分数环 + 彩色等级徽章,视觉最重但承载的信息只有"分数"。
!
两个反馈卡(绿底/橙底)并排,彩色面积大;违规/轮次卡片还带彩色左边条。

建议

结果页做"3 个层次":① 顶部白卡:分数(大号数字)+ 等级 + 一句话总结;② 中间:五维 + 综合评价合并为一张卡;③ 反馈(做得好/下一步)用两栏浅底卡(取消强色边条,改用图标+文字)。违规与轮次点评折叠:默认只显示数量和第一项,点击展开。操作区精简:主按钮 1 个(下一场/复练)+ 次级按钮 2 个,链接收进"更多"。

roleplay-result · 患者模拟复盘页

!
同样是蓝底 hero + 装饰圆(hero-deco),与 result 页风格重复,两个"结果页"观感雷同。
!
总结卡引号排版、编号原则卡,信息本身清晰;主要问题仍在头部与整体蓝调。

建议

与 result 页统一为白卡 hero,去掉装饰圆;保留"整体接待总结 → 已覆盖问题 → 关键原则 → 后续建议"的线性结构,这是一页好内容,只需去装饰、留呼吸感。

mine · 个人中心

!
信息量大(hero + 3 统计卡 + 签到 + 打卡列表 + 日历 + 积分规则 + 4 个工具卡),签到/日历/积分对"训练型产品"是次要功能,却占了近半屏。
!
hero 大色块 + 渐变 + 角色切换胶囊,又是重装饰;4 个学习工具卡各有彩色图标底,彩色密度高。
!
骨架屏与加载态齐全(值得肯定)。

建议

学习工具置顶:个人成长的入口(成长/错题/话术/收藏)提到 hero 下方,签到日历折叠进"我的成长"二级区。hero 改白或浅色渐变,角色切换降为普通文字按钮。工具卡图标统一用单色线性图标,取消彩色底,用"深蓝图标 + 白底"保持克制。

phrases · 话术锦囊

!
页面结构清晰(切换 + 搜索 + 列表),主要问题是每张话术卡彩色标签较多(场景标签 + 轮次标签 + 收藏/复制/训练三个操作)。
!
"患者关切 / 推荐表达"两段文本的层级靠彩色小标题区分,可读性依赖颜色。

建议

标签降噪:场景名用普通加粗文字,轮次用小号灰字;推荐表达用深蓝文字 + 浅蓝灰底突出,患者关切用灰字,减少彩色胶囊。操作区右侧排布,主操作"复制"用文字按钮即可。

mistakes · 错题复练

!
卡片结构清楚(当时表达 → 为什么 → 建议改写 → 操作),但"当时表达 / 建议改写"两处彩色底(蓝) + 优先级彩色标签,色彩偏多。
!
开关"显示已掌握项目"用系统 switch,与全局风格略脱节。

建议

仅"建议改写"用浅蓝底强调,"当时表达"用灰底;"为什么"纯文字。优先级标签保留但只用 2 档(优先/普通)颜色,中档用灰。switch 保留但可统一样式。

profile · 个人成长

!
数据页面,结构合理(统计 + 能力画像 + 弱点 + 走势),主要问题:五维横条用 3 色分档(绿/蓝/橙),"练习重点"每项都有彩色标签。
!
分数分档色(绿/蓝/橙)在多个页面重复出现,建议统一语义:达标=蓝、待提升=橙、违规=红,去掉"绿色=优秀"的额外档。

建议

能力横条统一用主色(深蓝),只对"最弱项"标橙;分数颜色跟随 tier 但减少色相种类。走势列表行内箭头/符号已克制,保持。

admin · 数据看板(主管)

信息架构好(概览 → 五维 → 场景 → 建议 → 成员),主要问题是头部蓝底 hero 与"主管"角色大色块,以及成员达标色环(绿/红)与彩色徽章。
!
锚点导航胶囊组,彩色密度高。

建议

hero 改浅色:白底 + 深色标题 + 细边框,与学员端保持同一设计语言;时间筛选用分段控件(白底细边框)。成员达标环保留(它是有意义的数据可视化),但降低饱和;锚点导航改文字链接 + 下划线态。

建议:沿用 admin 的改版方案,成员详情聚焦"五维 + 最近训练 + 建议",减少装饰。
