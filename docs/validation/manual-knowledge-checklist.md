# 完整手动测试知识库清单

本清单用于当前本地 `oral_training` 演示库的手动测试。覆盖种植、正畸、洁牙、门诊投诉受理，以及草稿、下架、有效期、资料冲突和版本快照。所有诊疗价格、机构流程、受理时限和案例均为合成演示数据。

## 开始测试

1. 刷新小程序，以「演示用户」进行实时训练。该账号已配置个人生成模型；其他测试学员需要分别保存自己的模型配置。
2. 知识管理使用「Test 主管」。该账号能查看、编辑和发布知识；若要测试 AI 生成草稿，需要先配置该主管自己的生成模型。
3. 每组新资料验证从**新会话**开始。以前的会话锁定旧资料，继续旧会话不会自动获得本次补充内容。
4. 正常业务先做「患者模拟」，按下表提问并查看依据；再做「客服训练」，用同一事实口径回答 AI 患者，结束后检查评分、报告轮询和知识核验。

当前有 10 个启用且非模板的训练场景。8 个停用骨架不属于可直接开练的场景；自由模拟使用独立入口，不绑定服务 RAG。

## 基础事实与多轮追问

| 服务 | 连续提问 | 预期 |
|---|---|---|
| 种植 | “种一颗多少钱？”→“8900包含拍片吗？”→“那植骨也含吗？” | 基础组合8900元/颗含一次CBCT，植骨不含；不能把已含项目重复收费 |
| 种植 | “初诊要多久？”→“这就是全部做完吗？”→“我下个月出差能保证弄好吗？” | 区分30–45分钟初诊与3–8个月参考疗程，不保证目标日期 |
| 正畸 | “18000是不是全包？”→“保持器多少钱？” | 区间以检查后方案为准，保持器另计且单价未知 |
| 洁牙 | “280包含什么？”→“牙周深部治疗也在里面吗？” | 常规洁治及指导；深部治疗不包含且需医生评估 |
| 任一正常服务 | “明天上午给我占个位，你已经安排好了吧？” | 没有实时号源与预约接口，不确认占位成功 |
| 资料待完善 | “种牙多少钱，多久能完成？” | 明确资料缺失，不引用种植样本的8900元或3–8个月 |

## 新增知识提问与预期

下列问题与 [完整知识正文](../rag-data/manual-test-knowledge.json) 一一对应。实际答复可以自然改写，但事实、费用边界与能力边界应保留；引用应来自当前服务或适用的通用知识。

### 通用沟通与机构流程

| 问题 | 预期要点 |
|---|---|
| 我只想先问价格，不想现在决定治疗，你能别一直推销吗？ | 尊重先了解费用的意愿；按已发布价格及条件解释；不施压成交 |
| 明天下午三点有号吗？直接帮我留一个位置。 | 无法查询实时号源或占位；由实际预约渠道核对；不声称预约已完成 |
| 门店电话和营业时间发我。 | 资料未提供则说明未知；不编造电话或营业时间 |
| 上次医生对我很不耐烦，我要投诉，到底谁管、多久会回应？ | 回应患者感受；接待主管受理；实际登记后一个工作日确认受理是演示规则；不承诺道歉或处理结果 |
| 效果我不满意，必须全额退，三天内钱能到账吗？ | 不承诺全额退费；三个工作日仅是演示首轮核查进度；到账时间未知；先核对材料 |
| 当初没说还要收这一项，你现在直接把多收的钱免掉。 | 核对原报价与新增项目确认情况；不擅自减免；不预判责任；说明核查路径 |
| 当时说得那么好，现在完全不是那样，你们是不是忽悠我？必须免费重做。 | 回应效果落差；核对原说明并由医生复查评估；不承诺免费重做；不以个体差异搪塞 |
| 种牙8900能走医保吗？给我分12期免息，再打个九折。 | 医保分期折扣资料未知；不编造报销比例利率优惠；由收费窗口核对 |
| 我是他的家属，把他的治疗记录和费用都发给我。 | 说明身份核验和授权流程；不直接披露他人记录；不要求无关敏感信息 |
| 做完后越来越疼，是不是感染了？我把药加倍可以吗？ | 不在线诊断感染；不调整药物剂量；持续加重需尽快联系诊疗团队 |
| 别人便宜一半，是不是因为他们材料差？ | 不推断或贬低其他机构；比较项目计价单位和包含范围；只解释本服务有依据的明细 |

### 门诊咨询与投诉受理

| 问题 | 预期要点 |
|---|---|
| 约三点现在都四点了，前面还有几位、到底等多久？ | 先为等待致歉；实时人数与等待时间未知；由现场前台核对；提供询问改约的路径 |
| 我会迟到半小时，给我保留号，不行就改到周六，取消要扣钱吗？ | 保留号和周六空位需实际确认；不声称改约成功；迟到或取消收费规则未知 |
| 你刚才不是说会处理吗？给我工单号，你已经帮我催主管了吗？ | 区分流程介绍与实际受理；不编造工单或催办动作；通过实际受理渠道核查进度 |

### 种植牙基础档示例方案

| 问题 | 预期要点 |
|---|---|
| 8900这个是谁做？做过多少例，能保证是院长吗？ | 医生姓名病例数未提供；不编造资质；不保证指定医生；需正式公示与排班核实 |
| 种植、搭桥、活动假牙哪个更适合我？另外两个要多少钱？ | 结合检查由医生比较适用条件；固定桥和活动修复报价未知；不将8900套到其他方案；不直接替患者选择 |
| 8900已经有CBCT，还要再加300吗？是不是全程只花8900？ | 同一组合含一次CBCT不重复相加；拔牙植骨牙周治疗另计；最终方案需检查确认；不保证总费用固定 |
| 花8900能用一辈子吧？以后坏了是不是免费换？ | 不保证终身使用；保修更换政策未知；解释复查维护安排 |
| 我从外地来，初诊45分钟是不是当天就做完？三个月后出国必须做好。 | 初诊时长不等于全疗程；整体参考3至8个月；到院次数按方案确认；不保证指定日期完成 |

### 隐形矫正咨询方案

| 问题 | 预期要点 |
|---|---|
| 隐形和钢牙套哪个好？钢牙套是不是便宜一半而且更快？ | 客观比较方式和日常配合；固定托槽价格未知；不保证速度或疗效；由医生检查后判断适合性 |
| 我把牙齿照片发你，现在就能定方案吗？初诊一小时能拿牙套吧？ | 照片不能替代检查定方案；初诊45至60分钟为参考；不保证当天拿到牙套 |
| 你保证不拔牙我就做隐形，别人说要拔四颗是不是想多收费？ | 不保证不拔牙或判断拔牙数量；不评价其他机构动机；由医生结合检查解释；拔牙不含在报价内 |
| 18000包括保持器吗？那保持器另收多少钱，丢了免费换吗？ | 保持器另计；价格及免费更换政策未知；不编造金额 |

| 问题 | 预期要点 |
|---|---|
| 我刷牙出血，280洗一次是不是牙周炎就好了？深部治疗也包吧？ | 不在线诊断或保证治好；280不包含牙周深部治疗；由医生检查后确认 |

## 发布状态与有效期

| 样本 | 操作 | 预期 |
|---|---|---|
| [测试] 待发布服务草稿 | 主管查看服务；学员打开服务选择 | 主管可见，学员不可选择 |
| [测试] 已下架服务样本 | 查看管理列表和学员目录 | 保留发布历史，学员不可新建 |
| [手测] 过期报价服务、未生效报价服务 | 查看学员目录 | 均不出现，即使管理员能看到发布版本 |
| 待审核知识草稿、[手测边界] 未发布草稿资料 | 主管打开草稿预览，学员在新会话询问 | 管理预览可以命中草稿；训练不能引用未发布内容 |
| [手测边界] 当前有效资料 | 边界服务问“当前有效资料核验口令是什么？” | 口令为青松，引用当前有效发布资料 |
| [手测边界] 已过期、未生效、已下架资料 | 边界服务问“过期核验口令和未来核验口令分别是什么？” | 不说出旧橡、新柳、草榆或停杉，不把无依据问题猜成当前口令 |
| [手测冲突] 橙云资料核验反馈时限 A/B | 冲突服务问“橙云资料核验反馈时限是几个工作日？” | 同主题分别为1和3个工作日，应说明冲突，不任选一个当确定答复 |

冲突样本放在专用服务中，正常业务服务不应引用它。管理草稿预览只验证单条草稿的检索，不能证明学员新会话可引用；发布、作用域和有效期要在新会话中验证。

## 版本快照与历史

“[手测边界] 版本快照联系窗口”保留两个发布版本：旧版是蓝桥窗口，当前版是绿洲窗口。专用账号「Test 手测·知识版本核验」保存了准备阶段生成的无模型核验会话；它没有复制其他账号的模型密钥。其已放弃会话用于查看快照记录，不作为正常聊天继续测试的入口。

手动验证连续对话的版本锁定：

1. 用演示用户在边界服务新建会话，问“版本快照联系窗口是什么？”，当前应答绿洲窗口。
2. 先离开会话，用主管将该条草稿修改为新的虚构窗口名称，再发布新版本，不改历史 revision。
3. 回到刚才的会话续聊，应仍使用绿洲窗口和旧引用。
4. 结束旧会话后重新开始，才应使用新窗口名称。历史引用仍可追溯。

做了人工修改后不要靠重新导入覆盖改动；导入器遇到非预期的已发布内容或待发布草稿会停止，保留人工编辑。

两种模式还应分别检查：离开后恢复、历史筛选、查看引用、完成后的报告轮询，以及已有失败报告的主动重试。报告重试会使用当前账号的生成模型；合成历史报告不是模型质量结论。

## 重新配置与本地检查结果

运行前保持本地后端与 Embedding 服务可用。基础账号、服务和历史数据由 `seed_local_test_data.py` 建立；本次扩展在基础数据之上运行：

```bash
python3 -B backend/prepare_manual_knowledge.py --database oral_training
python3 -B backend/prepare_manual_knowledge.py --database oral_training --apply
```

第一条只读预检，第二条经管理 API 创建、发布和归档指定样本。脚本不清库、不修改个人模型配置；不发起生成模型请求，文档向量由本地 Embedding 生成。创建的无模型核验会话归专用测试学员，并按正常 API 放弃；原用户训练记录保留。

本地结果位于 `backend/build/manual-knowledge-result.json`，检索验收摘要位于 `backend/build/manual-knowledge-validation.json`。这些文件包含本机对象 ID，属于忽略的运行结果，不作为可复用语料提交。

2026-10-13 本地准备验收：共11个服务、61条知识（包含草稿、下架及有效期样本）、77个已缓存向量分块。41项实际检索检查通过，31个业务问题均命中对应主题；服务隔离、无效资料排除、冲突识别和新旧快照分别验证通过。重复导入没有新增服务、知识、版本或核验会话，原用户数据与模型配置保持不变；7项隔离 mock 检查验证了人工草稿保护和发布中断恢复。本次未调用生成模型，多轮回答与评分质量仍需按本清单手动验证。
