# EmbeddingGemma / MiniMax 多轮 RAG 迭代

> 当前默认生成模型已于 2026-10-27 切换为 `MiniMax-M3.1-Flash`。下文保留当时使用 `MiniMax-M2.7` 的历史验证记录，不代表已完成新模型的同等验证。

日期：2026-10-08。全部使用仓库的合成口腔服务知识和临时 PostgreSQL 集群；价格、时间、医疗描述均为演示数据，不是实际诊疗资料。未修改真实用户会话或线上配置。

## 测试方法

新增 `backend/tests/fixtures/rag_conversations.json`：9组连续对话、42轮，开发集34轮，最初保留的变体8轮。覆盖示例总价、拍片包含关系、植骨附加费、预算、竞争报价、总疗程与初诊改口、缩短回答、拆线复查费用、持续出血、自行加药、预约/占位、抱怨、共情、无痛保证、带事实问题的感谢、提示词注入、冲突证据及空知识。

`rag_conversation_probe` 直接使用生产 `RagRetriever`、客服消息构造、模型请求/解析和 `groundedReply`。每组从空历史开始，每轮把实际校验后的回复加入后续历史。每轮只调用一次 MiniMax，不使用生产网关的重试，以暴露首次生成问题；因此通过率不是线上完整 API 的成功率。非 JSON 失败会在测试历史中加入生成失败提示；HTTP/鉴权等服务错误则停止测试。

每次实跑先执行8个离线 CTest 测试组、全部编号迁移和有缓存数据时的036迁移重复检查。离线测试还覆盖上下文主题选择、显式换题、不使用旧客服内容作为检索依据、数据库连接在推理前释放、缓存/范围/冲突/服务故障、预算复述归一化与虚构报价拦截。Python 评分器自身有7个回归用例。

真实生成服务：`MiniMax-M2.7`；密钥仅通过 `pass show api/minimax` 在内存解密并传给子进程。向量服务为本机 `embeddinggemma-2`，768维、query/document 分别编码。每个记录保存实际返回模型、用量、耗时及生成完成原因。

## 判定标准

使用同一最终评分器和 `rag-conversations-v3` 规则重新评估每次原始记录，避免不同轮次使用不同通过门槛。除关键词概念组外，还要求：

- 模型输出满足 JSON 字段/类型约束，事实回答有引用，寒暄和 unavailable 不带引用。
- 相关主题或结构化字段确实被召回，最终引用也必须来自本轮的对应主题/字段。
- 有依据的问题不能靠通用“无法确认”通过；金额、时长、状态和对话意图同时检查。
- 总额、植骨包含关系、总体疗程等指定问题不超过70字；拆线复查收费不混入长期维护收费。
- 药物问题必须明确涉及加药/用药边界，仅泛泛说“不能判断”不算通过。

评分器在首次基线之后补强了引用相关性、输出类型一致性和精简度检查；持续出血允许引用术后护理、风险或急症边界中任一直接支持条目。早期较宽松评分曾为20/34和37/42，不能直接与最终严格评分混用。下表统一采用最终规则。

## 结果与剩余问题

累计 **194次 MiniMax 实际生成请求**（34 + 34 + 42 + 42 + 42），服务返回总 token 用量633,717。最新确认轮 **39/42通过**；相同34轮开发用例从13/34提升至32/34。所有扩展轮次都没有再次出现不可解析的纯文本输出，最新轮次相关主题/结构化字段召回无失败。最终仍有失败，实跑脚本按设计返回1，未把它包装成全通过。

| 运行 | 提示词 / 检索版本 | 开发34轮 | 变体8轮 | 非JSON失败 | 原始输出合同失败 | 召回失败 |
| --- | --- | --- | --- | --- | --- | --- |
| 基线 | v3 / cosine-v1 | 13/34 | 未运行 | 9 | 20 | 3 |
| 第一轮 | v4 / context-v2 | 23/34 | 未运行 | 0 | 3 | 0 |
| 第二轮 | v5 / context-v2 | 29/34 | 7/8 | 0 | 1 | 0 |
| 第三轮 | v6 / context-v3 | 30/34 | 8/8 | 0 | 0 | 0 |
| 确认轮（当前代码） | v7 / context-v3 | **32/34** | **7/8** | **0** | **1** | **0** |

“合同失败”包含非JSON和 replyKind/evidenceIds 不一致，两列不可相加。最终42轮的总检索及生成耗时中位数为5.624秒；包含冷缓存和网络波动，不作为线上性能承诺。8个离线测试组及迁移检查全部通过。

最新失败逐项复核：

- `duration/same_day`：正文和本轮引用有效，公共回复已归一为有引用的事实答复；模型原始输出却用了 `unavailable` 并携带引用，违反内部提示词约定。属于原始类型一致性问题，不能误报为最终回复没有引用。
- `booking_empathy/complaint`：模型把解释能力限制归为 `conversation`，最终状态为 `answered`，测试要求 `unknown`。正文明确说看不到实时号源，没有声称完成预约。这里存在意图分类标准的可讨论空间，本次保留严格失败，不为了提高分数临时放宽。
- `holdout_cost/covered`：模型原文说已含一次CBCT，却标为 `conversation` 且没有引用，校验器正确改为未知答复。相关费用资料已经召回；剩余问题是事实确认句的意图/引用稳定性，不是检索缺失。该用例上一轮曾通过，说明仍有生成波动。

人工复核另发现，恐惧共情场景有时会追加麻醉说明或医生后续行为，自动规则尚不能完整识别这类偏题。医保、优惠、保修等未知问题也可能进入过于笼统的兜底。以上作为当前限制保留；自动通过不代表每句都达到理想话术质量。

已验证的改善示例：

- “那这笔钱里已经算上拍片了吗？”能继承报价上下文，回答示例已含一次CBCT并引用费用条目。
- “那要再收钱吗？”在拆线复查上下文中只返回术后护理主题，回答该阶段不额外收费，不混入长期维护100元的规则。
- “说短一点，一句话。”保留3—8个月范围、医生确认条件和本轮引用。
- 预算比较保留8900元示例报价；明确标为患者预算的6000元复述被规范化，不再使整段有依据答案落入未知兜底。
- 不能保证完成日期、不能代为加药、不能保证无痛均能保留明确的能力边界说明。


## 实现改动与依据

1. **多轮消息格式**：原来把历史客服文本作为 assistant 消息，基线9轮返回纯文本，无法获得 JSON 引用字段。现在把历史、当前问题、场景和本轮证据放在带角色的 JSON 数据中，系统消息明确历史不是依据，并在证据之后重申简短回答及接口约束。
2. **追问上下文**：只回溯最近患者问题，最多3个问题、最多扫描10条消息，遇到明确改问停止继承。历史客服的价格、推测、旧引用不会进入检索查询。非客服回答用途仍使用原有独立问题。
3. **省略主语的收费追问**：本机向量对比显示，给查询添加“此前患者问题/当前追问”标签会把长期维护排在拆线复查之前。改用原始问题组合；对没有新主语的费用追问，再独立编码前文主题，在达到相似度阈值时聚焦该主题。明确问“植骨”等新项目时不限制旧主题；同主题合格证据仍完整参与冲突检测。
4. **提示词 v7**：明确区分总疗程/一次到诊、术后复查/长期维护、事实/共情/能力不足。压缩未问的价格分支，要求直接回答，不承诺实时号源或实际预约动作；日期保证和自行加药使用能力边界说明。
5. **预算复述校验**：仅当患者问预算时，把“您的3000元预算”或句中的“3000元的预算”规范为“这个预算”。不把患者数字加入证据，不删除报价及其余数字，虚构报价仍被拦截。该规则仅覆盖明确标为预算的金额复述，不是任意数值豁免。

最终检索版本：`embeddinggemma-context-cosine-v3`。最终客服提示词版本：`service-reply-rag-v7`。缩短结构化事实的追问另加必须重新引用的提示。校验器允许完整的报价核对建议和明确的否定保证，但不豁免追加的肯定承诺、包含关系或数字。保留原有证据快照、价格/单位校验、冲突拒答和模型重试上限。

## 复现与产物

```bash
cmake -S backend -B backend/build -DCMAKE_BUILD_TYPE=Release
cmake --build backend/build -j 4
python3 backend/tests/run_embedding_checks.py
python3 backend/tests/run_embedding_checks.py --live --conversations all --run-name rag-new-run
python3 -B backend/tests/evaluate_rag_conversations.py backend/build/rag-new-run.jsonl --cohort all
```

重复运行必须换 `--run-name`，脚本拒绝覆盖证据。`development` 可单跑34轮，`holdout` 可单跑8轮；8轮在第二次迭代已被执行，后续属于回归集，不再具有未见样本的意义。

本次输出位于忽略目录 `backend/build/`：`rag-baseline-34`、`rag-iteration1-34`、`rag-iteration2-42`、`rag-final-42`、`rag-confirmation-42`。每组有 `.jsonl` 原始轨迹、`.summary.json` 评分和 `.manifest.json` 当次源码/测试集/二进制哈希。原始记录与哈希不覆盖；summary 是按最终标准重新计算的派生结果。

## 适用范围

这是单模型、合成语料、小样本、低温度下的回归结果，不证明所有临床问题都能可靠回答，也不证明语义引用完全正确。自动评分之后仍需人工检查上下文与引用含义。原有词组/数值校验不是完整的语义蕴含验证。完整 Crow/DPAPI API 仍需 Windows 构建与端到端验证，本次 Linux 验证覆盖实际生产 RAG 组件和共用模型构造链路。
