# 标准客服自然表达实测（2026-09-29）

> 以下为合并前本地实测；上游增量 PR 验证另见 `rag-model-increment-review.md`。

使用当前账号的个人模型配置，经后端 ModelGateway 调用 `deepseek-flash`，走真实检索、引用校验和回复归一化链路。测试资料为项目中的模拟种植牙服务，不代表真实诊所报价或医疗建议。探针只读原会话的知识快照，不向原会话添加消息。

## 评估方法

人工逐条判断：是否直接回答本轮问题、是否接住上下文和情绪、是否有无关解释、是否忠实于证据。字数只是提示，短而答非所问仍算失败。固定问题集 10 条，另加最初未参与调整的 6 条问题；发现失败后做定向回归。因此这 6 条后续已成为开发测试，不能当作独立盲测准确率。

问题集保存在 `backend/tests/service_reply_cases.json` 和 `backend/tests/service_reply_holdout.json`。本地 `tmp/human-reply-*.jsonl` 保存逐轮真实输出；这些临时日志不作为版本库必备文件。不同采样仍可能有差异，本次结果不意味着任意问题都能达到同样效果。

## 发现与修复

- 基线中，“谢谢”“暂不预约”被换成待核实套话；现在普通聊天可无引用、无教学卡片，且通过真实消息保存链路。
- “一句话”“再简单点”丢失检索主题；现在根据最近实质患者问题检索，再压缩回答，不把模型旧回答当作知识。
- 预算、贵、当天等日常表达未匹配相应字段；补齐价格和疗程检索别名。
- 情绪交流容易变成麻醉流程讲解；强调回应具体经历，避免重复追问和不必要的面诊话术。
- 示例报价含一次 CBCT，但结构化包含项没有列出；回答限定为“示例报价包含”，不扩大成所有套餐承诺。
- “没法保证不疼”被误判为无痛保证；增加否定表达识别，同时测试肯定保证仍被拒绝。

事实答复仍保留引用、金额范围及单位校验、起价条件和必要适用限制。不会通过删除这些约束来换取简短。

## 验证范围

离线 CTest 和客户端静态检查通过；需要专用数据库配置的 3 个 CTest 项跳过。另运行隔离 PostgreSQL 的个人模型配置集成测试，验证普通聊天的空教学信息可以保存并读回。微信开发者工具中的视觉回归尚未执行。


## 最终抽样输出

最后一轮 10 个基础问题的回复为 4—53 字，未出现通用核实兜底；其中价格差异的“多半”仍偏推测，不能把本次人工评估当作事实正确率保证。四个定向问题复测为 9—54 字。

| 提问 | 实际回复 |
|---|---|
| 好的，谢谢你。 | 不客气。 |
| 我先考虑一下，暂时不约。 | 好，您先考虑，不着急。 |
| 太长了，一句话说清楚就行。 | 完整疗程通常约3—8个月，具体要医生检查后才能确认。 |
| 我平时要上班，只能周末去，能当天弄完吗？ | 整个种植流程没法当天做完，通常要分几次到诊；周末的号源还得确认一下。 |
| 这个价钱包拍片吗？ | 示例报价里含一次CBCT拍片；具体包含哪些项目还需按正式方案确认。 |
| 你就说能不能保证不疼，别绕。 | 不能保证完全不疼。 |

真实 API 连续对话中发现过一次致谢被降级，随后复测正常；为避免依赖采样运气，最后增加了仅针对独立致谢的精确兜底。它不匹配“谢谢，那多少钱？”等包含实质问题的消息，且不会因此自动结束会话。该分支有离线回归测试。

本地后端已更新。真实接口验证了拒留电话、疗程提问、致谢三轮的保存和读回，测试会话用专用 ID 创建并放弃；原训练会话未变动。小程序 WXML 的隐藏空教学卡片变更需在微信开发者工具重新编译生效。
