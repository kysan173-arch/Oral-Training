# 模块 3 培训运营 + 模块 4 数据报表 实现计划

## 范围（用户已确认）

- **模块 3 培训运营**：完整闭环——建表 + 发布 + 追踪。
- **模块 4 数据报表**：本期只做违规词 Top N + 排行榜，**报表导出放后续**。
- **排行榜**：四维度切换（周训练时长 / 月平均分 / 累计通关数 / 连续打卡天数）。
- **零订阅消息**：本期不做推送，banner 仅前端判断；`PATCH .../notify` 降级为"复制未完成名单文本"。

## 关键工程决策（不在用户回合内追问）

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| A. 违规词数据通路 | **A.3 新增 `risk_flags` 表 + finalize 时硬编码规则引擎** | A.1 改 DeepSeek prompt 触 AGENTS.md 兼容敏感区（reliable_store.h 1006/1300）；A.2 正则无 round/场景上下文；A.3 ~30 行 C++，原生支持 TopN+下钻+筛选，零 AI 改动 |
| B. 培训计划接收人 | **B.1 全团队** | 发布时批量 INSERT assignments，UI 无需多选；MVP 最简 |
| C. 完成判定 | **C.1/C.2/C.3**：`required_count` 题 + `required_pass_rate`% 通关 | 文档 3.3.1 原文 |
| D. 学员端接收页 | **D.1 首页 + 训练 Tab 双 banner + 新建 training-plans 页** | 触达率高，新页面独立 |
| E. 排行榜"通关" | **E.2 `evaluations.total_score >= 60` 次数** | 与"通关"语义一致 |
| F. 连续打卡天数 | **F.1 evaluations 按日聚合最长连续段** | 与现有 streak 算法同构 |
| G. finalize hook 完成判定 | **子查询重算（COUNT/AVG）而非 `+=`** | 天然幂等，无并发重复 |

## 第一阶段：后端（数据通路）

### 1.1 新迁移 `backend/migrations/010_training_plans.sql`

**`training_plans`**

- `id` UUID PK, `created_at` TIMESTAMPTZ DEFAULT NOW()
- `title` TEXT NOT NULL
- `period` TEXT CHECK(`period` IN ('week','month'))
- `scenario_ids` JSONB（数组，可空=全场景）
- `required_count` INT NOT NULL
- `required_pass_rate` NUMERIC(5,2) NOT NULL（百分比 0-100）
- `description` TEXT, `resource_links` JSONB
- `due_at` TIMESTAMPTZ NOT NULL
- `created_by` TEXT（admin user id）
- `status` TEXT CHECK(`status` IN ('active','expired')) DEFAULT 'active'
- 索引：`idx_plans_status_due(status, due_at)`、`idx_plans_created(created_at)`

**`training_assignments`**

- `id` UUID PK
- `plan_id` UUID FK → training_plans ON DELETE CASCADE
- `learner_id` TEXT（与现有 learners.user_id 类型对齐）
- `assigned_at` TIMESTAMPTZ DEFAULT NOW()
- `completed_count` INT DEFAULT 0, `avg_score` NUMERIC(5,2) DEFAULT 0
- `is_notified` BOOL DEFAULT false
- `status` TEXT CHECK(`status` IN ('pending','done','expired')) DEFAULT 'pending'
- 索引：`UNIQUE(plan_id, learner_id)`、`idx_assignments_learner(learner_id)`、`idx_assignments_plan(plan_id)`

### 1.2 新迁移 `backend/migrations/010b_risk_flags.sql`

**`risk_flags`**

- `id` UUID PK
- `session_id` TEXT FK → sessions ON DELETE CASCADE
- `learner_id` TEXT
- `scenario_id` TEXT
- `text` TEXT（归一化违规词，便于聚合）
- `category` TEXT, `category_label` TEXT
- `round` INT, `severity` TEXT CHECK(`severity` IN ('low','medium','high')) DEFAULT 'medium'
- `created_at` TIMESTAMPTZ DEFAULT NOW()
- 索引：`idx_risk_text_created(text, created_at)`、`idx_risk_learner(learner_id)`、`idx_risk_scenario(scenario_id)`、`idx_risk_created(created_at)`

**违规词模式（写在 reliable_store.h 内部硬编码常量，不入 SQL）**：

- 高风险：`"100%"`, `"保证"`, `"绝对"`, `"肯定能"`, `"一定能"`, `"包成功"`
- 中风险：`"我也不是很清楚"`, `"应该是"`, `"大概"`, `"差不多"`
- 自我暴露：`"我也是"`, `"我也"`, `"作为同事"`, `"实话说"`
- 不当承诺：`"不要钱"`, `"免费"`, `"退款"`, `"赔偿"`
- 共 ~20 条，启动时落表 `std::vector<RiskPattern>{regex, category, severity}`

### 1.3 新接口（在 `main.cpp` 路由表 1777 后追加，全部 `authorize`+admin 校验；学员端 `/api/learner/*` 用 `learner_only`）

| 方法·路径 | 鉴权 | 入参 | 出参 |
|---|---|---|---|
| `POST /api/supervisor/training-plans` | admin | `{title, period, scenario_ids[], required_count, required_pass_rate, description, resource_links[], due_at}` | `{plan, assignmentCount}`；事务内 INSERT plan + 批量 INSERT assignments（取 active learners） |
| `GET /api/supervisor/training-plans?status=active\|expired\|all` | admin | — | `{plans:[{id,title,due_at,required_count,required_pass_rate,assignmentCount,completedCount,avgScore}]}` |
| `GET /api/supervisor/training-plans/{id}` | admin | — | `{plan, assignments:[{learnerId,name,completedCount,avgScore,status,lastTrainingDate}], completedRate, avgPassRate}` |
| `PATCH /api/supervisor/training-plans/{id}/notify` | admin | — | `{pendingLearners:[{name,lastTrainingDate}]}`（降级：返回名单文本供复制） |
| `GET /api/learner/training-plans` | learner | — | `{plans:[{id,title,due_at,required_count,required_pass_rate,description,scenario_ids,completedCount,avgScore,status}]}` |
| `GET /api/supervisor/reports/forbidden-phrases?range=&category=&limit=` | admin | range=week\|month\|quarter\|all, category 可选 | `{phrases:[{text,category,categoryLabel,count,memberCount,scenarioDistribution}], range, totalSessions}` |
| `GET /api/supervisor/reports/forbidden-phrases/{text}/members` | admin | range 可选 | `{members:[{learnerId,name,count,scenarios:[{scenarioId,scenarioName,round}]}]}` |
| `GET /api/supervisor/reports/leaderboard?dimension=&limit=` | admin | dimension=weekly_sessions\|monthly_avg\|completed_scenarios\|streak_days | `{dimension, leaderboard:[{rank,learnerId,name,score,extra}]}` |


### 1.4 finalize hook（`reliable_store.h::saveEvaluation()`，约 715 行 `UPDATE sessions` 之后）

在同一事务 `tx` 内追加：

```cpp
reconcileTrainingAndRisk(tx, sessionId, userId, scenarioId, finishedAt, totalScore, reportMessages);
```

实现（伪代码）：
1. **写 risk_flags**：遍历 `RiskPattern`，对 `report["messages"]` 中每个客服消息做 regex 匹配，命中即 INSERT 一条。
2. **重算 assignments**（幂等）：

- 找出所有 active 计划，窗口包含 `finishedAt` 且 `scenario_ids` 包含当前 scenario 或为空
- 对每个匹配的 assignment：`UPDATE training_assignments SET completed_count = (子查询：plan 窗口内通过 sessions 数), avg_score = (子查询：plan 窗口内 AVG total_score) WHERE id=?`
- 若 `completed_count >= required_count` 且 `avg_score >= required_pass_rate` → `status='done'`；否则保持 `pending`

3. 事务边界：复用现有 `tx.commit()`，无需新增事务。

## 风险与边界

| 风险 | 应对 |
|---|---|
| AGENTS.md 兼容敏感区 | A.3 方案**不动** DeepSeek 链路；只读 `report["messages"]` 做后处理 |
| 推送能力缺失 | `PATCH notify` 降级为复制名单；前端 banner 仅本地判断 |
| 排行榜大团队性能 | 4 条聚合 SQL 均带索引（evaluations.created_at、total_score、user_id）；单次读事务 |
| finalize hook 重入 | 子查询重算天然幂等；同一事务内串行写 risk_flags + 重算 assignments |
| 新表与旧 9 个迁移共存 | 新表独立命名，旧 migration 一字不改 |
| 学员端 banner 误伤 | `wx:if` 严格控制，无 pending 计划时为空 |
