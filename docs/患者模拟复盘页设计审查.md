# 患者模拟复盘页设计审查与修改意见

> 页面：`pages/roleplay-result/roleplay-result.{wxml,wxss}`（48 + 56 行）
> 入口：历史记录 → 患者模拟 → 已完成记录 → 「查看复盘」
>
> **总体判断：骨架是好的** —— 结构清晰、**零硬编码色**、全部走设计变量、加载/超时/重试三态齐全。
> "怪"集中在两件事上：**字重只有一档（整页加粗）** 与 **正文行高过松**。
> 改动量很小（约 6 条 CSS + 2 处 wxml 微调），收益却很明显。

---

## 一、P0：真 bug（1 条）

### 1. 加载态卡片左右贴屏幕边，圆角被裁掉

```css
.loading-result { display: flex; min-height: 70vh; align-items: center; justify-content: center; }
.loading-card { width: 100%; padding: 48rpx 32rpx; border-radius: 20rpx; border: 1rpx solid var(--color-border); }
```

`.page-shell`（`app.wxss:56`）**只有 `padding-bottom`，没有左右 padding** —— 所以 `width: 100%` 的加载卡
会顶到屏幕左右边缘。一个带 20rpx 圆角 + 1rpx 描边的卡片贴边，左右圆角直接被裁掉。

**改**：补左右边距，与页面其他卡片一致

```css
.loading-card { width: auto; margin: 0 24rpx; padding: 48rpx 32rpx; }
```

> ⚠️ `pages/result/result.wxss:110-111` 是**一模一样的写法，同样贴边**，必须一起改。

## 二、P1：「怪」的主因（3 条）

### 2. 正文全部加粗 —— 整页没有「常规字重」这一层

| 选择器 | 现状 | 它其实是 |
|---|---|---|
| `.summary-quote` | 28rpx / **600** / 1.8 | 一段完整的总结文字 |
| `.topic-text` | 26rpx / **600** / 1.8 | 列表项正文（已覆盖问题、后续建议）|
| `.principle-text` | 26rpx / **600** / 1.8 | 列表项正文（关键服务原则）|

全页 `font-weight` 统计：**600 出现 10 次，400 只出现 1 次**（还是 `result-kicker` 那个小标签）。

结果：**标题和内容一样粗**，页面上没有轻重之分 —— 这是"看着怪"最直接的来源，每个字都在喊。

**改**：正文回 400，600 只留给标题与编号

```css
.summary-quote, .topic-text, .principle-text { font-weight: 400; }
```

### 3. 正文行高 1.8 偏松

26rpx × 1.8 = **47rpx 行高**。同样 26rpx 的正文，`pages/result` 用的是 `1.55`。
行高偏大与字重偏粗叠加，行与行之间发虚，整页也被拉长。

**改**：收到 1.6

```css
.list-card, .topic-text, .principle-text, .summary-quote { line-height: 1.6; }
```

### 4. 总结文字被中文引号包住 —— 读起来像「引用了别人的话」

```xml
<text class="summary-quote">“{{summary.summary}}”</text>
```

这是**系统的复盘总结**，加引号后读起来像"引用了患者或客服说过的话"——而 `pages/result` 里
用引号的恰恰是"你当时说的"**原话**。语义被带偏了。

**改**：去引号，用左侧色条表达"这是总结"

```xml
<text class="summary-quote">{{summary.summary}}</text>
```
```css
.summary-card { border-left: 8rpx solid var(--color-primary); }
```

## 三、P2：一致性与细节（4 条）

### 5. section 标题比卡片左缩 8rpx，没和任何东西对齐

`.section-title-row` 的实际左边距 = **28rpx（页面 wxss）+ 4rpx（`app.wxss:90` 的 `padding: 0 4rpx`）= 32rpx**，
而卡片是 `margin: 0 24rpx`。标题既没对齐卡片外边缘，也没对齐卡片内文（24 + 28 = 52rpx）。

页面 wxss 只覆盖了 `margin`，**没覆盖 `padding`，所以全局那 4rpx 会叠加**。

**改**：显式清掉

```css
.section-title-row { margin: 0 24rpx 14rpx; padding: 0; }
```

> ⚠️ `pages/result/result.wxss:24` 同样是 28rpx，**要一起改**，否则刚统一的规范又分叉。

### 6. 同一页里两种列表模式

| 区块 | 呈现方式 |
|---|---|
| 已覆盖的问题 | **一张卡**，项间用虚线分隔 |
| 关键服务原则 | **每项一张独立卡**（`wx:for` 挂在 `.principle-card card` 上）|

同页两种模式，页面节奏不匀：上半是"卡内列表"，下半突然变成"卡片堆"。

**改**：统一成卡内列表，减少卡片的视觉重量

```xml
<view class="principle-list card">
  <view class="principle-card" wx:for="{{summary.keyPrinciples}}" wx:key="*this">
    <view class="principle-index">{{index + 1}}</view>
    <text class="principle-text">{{item}}</text>
  </view>
</view>
```
```css
.principle-card { display: flex; align-items: flex-start; padding: 14rpx 0; }
.principle-card + .principle-card { border-top: 1rpx dashed var(--color-border); margin-top: 6rpx; padding-top: 18rpx; }
```

### 7. Hero 区：大对勾与「不含数值评分」的定位冲突，且三处重复表达「完成」

现状：`患者模拟完成 · 场景名` + **96rpx 圆圈里的 ✓** + `学习复盘已生成` + 时间。

- **语义冲突**：整页定位是"**不含数值评分**、帮助理解沟通结构"，而一个大对勾会给学员"我过了"的暗示，与下方 notice 的声明自相矛盾。
- **信息冗余**：kicker（"完成"）、对勾（"通过"）、标题（"已生成"）——三处在说同一件事。

**改**：去掉对勾、kicker 只留场景名（最克制）

```xml
<text class="result-kicker">{{scenario.name}}</text>
<text class="hero-title">学习复盘</text>
```
```css
.hero-icon { display: none; }
```

### 8. 细节补漏

| 项 | 现状 | 改 |
|---|---|---|
| 「后续练习建议」标题行 | 缺右侧 `.section-caption`（其余三个 section 都有）| 补 `{{summary.nextPracticeSuggestions.length}} 条` |
| `.disclaimer` | `wxss:47` 定义了，**wxml 里无人使用** | 删掉 |
| `notice-box` 与 `practice-card` | 同用 `--color-primary-pale`(#F5F8FC)，语义不同却同色 | 练习建议改 `--color-primary-light`(#EEF2F8)，或 notice 换中性灰底 |

## 五、确认没问题的部分（不用动）

- 全页**零硬编码色**（仅 `#F7F9FC`、`#fff` 作 fallback），色值全部走设计变量 ✓
- 区块划分清晰：总结 → 已覆盖问题 → 服务原则 → 练习建议 → 行动按钮，信息流合理 ✓
- 加载 / 超时 / 重试三种状态都有覆盖，且文案明确说明"任务仍在后台可靠执行" ✓
- `notice-box` 主动声明"不含数值评分、不构成医疗建议"，与患者模拟的功能定位一致 ✓
- `topic-item` 用虚线分隔而非实线，与"复盘/学习"的语调和得上 ✓
