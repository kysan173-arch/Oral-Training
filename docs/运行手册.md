|---|---|---|---|---|
| 主环境 | `C:\Users\23732\CodeBuddy\20260912152152` | 8080 | `oral_training` | 功能最全，含自建的 /v1 网关与复读守卫 |

### 第四环境比 0915 基线多了什么

### 第四环境与另外两套的取舍

- **删除了知识管理界面与接口**（跟随上游基线的产品决策）
- 但 **RAG 检索能力完整保留**，知识数据已整表搬迁（12 条知识 / 24 个检索块）

## 三、首次部署（已完成，此处仅作留档）

按顺序执行五步：

```powershell
cd D:\jinqiuze\Oral-Training-merge29

# 5) 启动后端并自检
powershell -ExecutionPolicy Bypass -File merge29-local\start-backend.ps1
powershell -ExecutionPolicy Bypass -File merge29-local\check-local.ps1
```

## 四、日常使用

### 启动（顺序不能颠倒）

**必须先起模型，再起后端**——后端启动时会探测模型端点是否可达。

```powershell
# 第 1 步：起本机模型（约 60 秒就绪）
powershell -ExecutionPolicy Bypass -File "C:\Users\23732\CodeBuddy\20260912152152\deploy\serve\start-llama.ps1" -Action all

# 第 2 步：起后端（8082）
powershell -ExecutionPolicy Bypass -File D:\jinqiuze\Oral-Training-merge29\merge29-local\start-backend.ps1
```


## 五、模型路由：哪个功能用哪个模型

共 **9 个用途**，全部可在 `merge29.env` 里单独调整，改完重启后端生效（**不需要重新编译**）：

| 用途 | 走哪个实例 | 说明 |
|---|---|---|
| `patientReply` | 基座 | AI 患者回话 |
| `trainingPlanDraft` | 基座 | 主管端批量生成训练计划（**循环调用，较慢**） |
| `evaluate` | 基座 | 五维评分 |
| `roleplaySummary` | 基座 | 复盘总结 |
| `singleRound` | 基座 | 错题单轮复练点评 |
| `trainingHint` | 基座 | 实时提示 |
| `knowledgeDraft` | 基座 | 知识草稿生成 |
| `standardService` | **微调** | 标准客服示范答复 |
| `groundedService` | **微调** | RAG 接地客服答复 |

**为什么这么分**：微调版（sft-v4）学的是"业务话术"，适合表达类任务；基座版（qwen3-4b-base）上下文更大（8192 vs 4096），适合理解与推理类任务。

**回落规则**：微调实例未配置或不可用时，`standardService` / `groundedService` 会自动回落到基座——服务仍可用，只是话术风格不同。

## 六、切回云端 DeepSeek（对照或应急）

```powershell
# 切到云端（会自动备份当前配置）
powershell -ExecutionPolicy Bypass -File D:\jinqiuze\Oral-Training-merge29\merge29-local\switch-to-deepseek.ps1 -DeepSeekApiKey sk-你的密钥

# 切回本机双模型
powershell -ExecutionPolicy Bypass -File D:\jinqiuze\Oral-Training-merge29\merge29-local\switch-to-deepseek.ps1 -RestoreLocal
```

**只改配置并重启，不重新编译。** 切换后**RAG 检索链路完全不变**（检索走本地 PostgreSQL，与模型无关）。

> 提示：如果只是不想依赖云服务，**默认就是本机双模型，不需要执行本脚本**。

## 七、演示要点（避免踩坑）

| 要点 | 说明 |
|---|---|
| **先起模型** | 模型没起时，任何 AI 操作返回 **503** |
| **选对场景** | RAG 只对**绑定了服务**的场景生效：**种植牙基础 / 术后不适 / 比价**。自由模拟、正畸场景**不会**返回"查看依据" |
| **预热一次** | 首次请求包含模型预热，比较慢。演示前先随便问一句 |
| **评分要等** | 本地 4B 生成完整评分报告约需数分钟，属正常 |
| **一次一人** | 两个模型实例都是 `--parallel 1`，多人同时操作会排队 |
| **知识范围** | 知识库只覆盖**种植牙**一个方向（12 条），问其他科室会答"资料里没有" |
| **环境选开发版** | 否则小程序拒绝 `127.0.0.1` |

## 八、排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| 请求返回 **503** | 本机模型没起 | 执行第四节的第 1 步 |
| 打不开小程序 / 连不上 | 后端没起，或环境选了体验版 | 起后端；把开发者工具切到「开发版」 |
| 客服答复**没有"查看依据"** | 该场景未绑定服务 | 换用**种植牙基础 / 术后不适 / 比价** |
| 启动报 `MODEL_BASE_URL is set but MODEL_BASE_NAME is empty` | 配置缺名字 | 补 `MODEL_BASE_NAME` / `MODEL_TUNED_NAME` |
| `modelConfigured = false` | 未配置本地端点且无云端密钥 | 检查 `merge29.env` 的 `MODEL_BASE_URL`，或切云端 |
| 后端启动即退出、日志为空 | `DATABASE_URL` 密码错误 | 核对 `merge29.env` |
| 编译报 **C1128 节数超过限制** | 缺 `/bigobj` | 用 `build-backend.ps1 -Reconfigure` 重新配置 |
| 脚本报 `Missing closing '}'` | 脚本文件缺 UTF-8 BOM | 存为「UTF-8 带 BOM」 |
| 迁移报外键约束失败 | 知识表有**循环外键** | 用 `import-knowledge.ps1`（已内置 `--disable-triggers`） |
| 批量生成训练计划很慢 | 逐学员调用本机模型 | 属预期；可把该用途改为云端（见第五节） |

## 九、已知边界（如实说明）

| 项 | 现状 |
|---|---|
| 知识管理界面 | **已删除**（跟随上游基线）。知识只能用脚本或 SQL 维护 |

## 十、环境变量速查（`merge29.env`）

| 变量 | 当前值 | 作用 |
|---|---|---|
| `DATABASE_URL` | `postgresql://oral_training_app:...@127.0.0.1:5432/oral_training_merge29` | 独立数据库 |
| `MODEL_BASE_URL` | `http://127.0.0.1:8001/v1` | 基座实例 |
| `MODEL_BASE_NAME` | `qwen3-4b-base` | 须与 llama 启动别名一致 |
| `MODEL_TUNED_URL` | `http://127.0.0.1:8002/v1` | 微调实例 |
| `MODEL_TUNED_NAME` | `sft-v4` | 须与 llama 启动别名一致 |
| `MODEL_TIMEOUT_MS` | `600000` | 10 分钟，本机长输出所需 |
| `MODEL_ROUTE_*`（9 项） | 见第五节 | 按功能路由 |
| `BIND_ADDRESS` / `PORT` | `127.0.0.1` / `8082` | 仅本机监听 |
| `AI_WORKER_CONCURRENCY` | `1` | 后台任务并发 |

**未配置 `MODEL_BASE_URL` 时**：整体走云端 DeepSeek，行为与上游原版一致（向后兼容）。
