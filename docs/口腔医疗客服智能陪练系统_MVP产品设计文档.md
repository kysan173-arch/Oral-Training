# 1. 产品定位
## 1.1 产品定义
面向新入口腔客服的 AI 模拟对练微信小程序。用户选择典型口腔客服场景后，以普通客服身份与 AI 患者进行5—10轮文字对话；训练结束后，系统基于完整对话生成五维评分、违规说明和改进建议，并保存训练报告与历史记录。

MVP 用于完成大创结题与现场演示，验证大语言模型在患者角色扮演、上下文保持和话术自动评价中的产品闭环。当前版本不作为真实医疗咨询系统，不用于员工正式上岗判定、绩效考核或患者诊疗。

## 1.2 核心价值主张
| **面向对象** | **核心问题**                                                       | **MVP 解决方式**                                                    | **演示价值**                                   |
|--------------|--------------------------------------------------------------------|--------------------------------------------------------------------|------------------------------------------------|
| 新入口腔客服 | 缺少真实沟通经验；面对专业咨询、比价和术后不适时容易紧张或越权回答 | 提供固定患者画像、多轮对话、隐藏信息和自动反馈，允许低风险反复训练 | 展示 AI 陪练如何辅助客服发现知识、沟通和合规问题 |

## 1.3 产品目标
- 跑通“场景选择—多轮对话—结束训练—自动评分—查看报告—历史回顾”的完整闭环。

- 完成4个具有代表性的口腔客服训练场景，体现不同患者诉求、情绪和隐藏信息。

- 通过 Prompt 让通用大模型稳定扮演患者，并根据用户回答产生基本情绪变化。

- 通过独立评分调用生成结构化五维评价，识别严重医学错误和不合规承诺。

- 使用 PostgreSQL 保存会话、消息、评分和训练时间，为后续接入 LoRA 模型预留统一接口。

## 1.4 MVP 与研究成果的关系
| **成果类型** | **本阶段内容**                                               | **与 MVP的关系**                               |
|--------------|--------------------------------------------------------------|-----------------------------------------------|
| 模型研究成果 | 口腔语料库、LoRA 微调模型、微调前后效果对比                   | 独立完成研究验证；当前 MVP 暂不在线部署微调模型 |
| 产品演示成果 | 微信小程序、AI 患者、自动评分、训练报告、历史记录、演示数据页 | 通过通用大模型 API 与 Prompt 快速验证产品闭环     |
| 后续集成     | 将微调模型封装为兼容接口                                     | 替换模型服务地址，不改变小程序主要业务流程    |

## 1.5 成功标准
在现场演示中，评审人员能够从4个场景中任选一个，与 AI 患者完成至少5轮对话，主动或自动结束训练，随后看到合理的五维评分、违规原因和改进建议，并能从历史记录再次查看完整对话和报告。

# 2. 目标用户与使用场景
## 2.1 核心用户画像
| **角色**     | **典型状态**                                    | **核心诉求**                                           | **MVP 权限**                            |
|--------------|-------------------------------------------------|--------------------------------------------------------|----------------------------------------|
| 新入口腔客服 | 入职0—3个月，熟悉基础工作流程但缺少复杂对话经验 | 随时练习典型场景；知道哪里回答不当；理解何时应转接医生 | 场景训练、查看结果、查看历史和演示数据 |

## 2.2 典型痛点
- 掌握的口腔知识不系统，面对种植牙、正畸等问题时容易回答过度或表述不准确。

- 遇到比价、质疑或焦虑患者时，缺少需求挖掘和情绪回应策略。

- 对“客服可以解释什么、必须交由医生判断什么”缺乏明确边界。

- 传统培训需要资深员工陪练，难以随时复现同一情景并提供结构化反馈。

## 2.3 核心使用场景
用户在结题演示或自主练习时打开小程序，选择一个训练场景，阅读患者基础画像后开始文字对话。AI 患者根据预设人设、隐藏信息和当前情绪进行回复；用户完成5—10轮后主动结束，系统生成训练报告。用户可再次进入同一场景重练，也可在历史记录中回看此前表现。

## 2.4 产品使用边界
- AI 扮演的是模拟患者，不是真实患者，也不提供诊断或治疗建议。

- 用户是普通客服，不应替医生进行个体化诊断、确定治疗方案或作疗效保证。

- 自动评分主要用于技术演示和训练反馈，暂不具备专家审核基础。

- 系统不处理真实患者身份信息，不接入真实诊所业务数据。

# 3. 功能体系
MVP 只保留演示所需的最短业务链路，共6个页面。产品不设置正式登录和主管端，默认使用固定演示用户。

## 3.1 演示首页
功能说明：小程序默认落地页，用于说明产品定位并提供主要入口。

| **页面内容** | **具体要求**                                                         |
|--------------|----------------------------------------------------------------------|
| 产品简介     | 显示“AI 模拟患者、多轮对练、自动评分”的简要说明，并标注当前为演示版。 |
| 开始训练     | 进入场景选择页，是首页主按钮。                                       |
| 历史记录     | 查看已完成和未完成训练。                                             |
| 演示数据     | 查看训练次数、平均分等汇总数据。                                     |
| 测试用户提示 | 显示当前使用固定演示账号，不进行微信授权。                           |

不包含：热门话术轮播、搜索、打卡、积分、等级、排行榜和登录授权。

## 3.2 场景选择页
功能说明：展示4个固定训练场景，是进入对练页面的唯一入口。

| **展示项**    | **说明**                                                       |
|---------------|----------------------------------------------------------------|
| 场景名称      | 种植牙基础咨询、正畸基础咨询、与其他诊所比价、术后不适咨询。   |
| 场景简介      | 用1—2句话描述患者当前诉求和沟通背景。                          |
| 难度          | 基础或进阶，仅用于帮助用户选择。                               |
| 训练重点      | 列出本场主要考察能力。                                         |
| 患者基础画像  | 展示年龄、主要诉求和初始情绪，不展示隐藏信息。                 |
| 开始/继续按钮 | 无进行中会话时显示“开始训练”；存在进行中会话时显示“继续训练”。 |

重新开始规则：若同一场景存在未完成会话，用户选择重新开始时，旧会话标记为“已放弃”，新建训练会话。

## 3.3 对练舱
功能说明：系统核心体验页，采用微信聊天气泡样式，用户扮演普通客服，AI 始终扮演当前场景中的患者。

| **能力**     | **MVP 要求**                                                  |
|--------------|--------------------------------------------------------------|
| 文字对话     | 用户在输入框发送文字，AI 返回患者回复。                       |
| 多轮上下文   | AI 能够记住前文中出现的价格、担忧、用户承诺和已披露信息。     |
| 固定患者画像 | 每场训练绑定固定年龄、诉求、性格、初始情绪和隐藏信息。       |
| 基本情绪变化 | 根据用户是否共情、追问、越权或强推，更新患者的内部情绪状态。 |
| 有限隐藏信息 | 患者不会一次性说出全部顾虑，需通过用户询问逐步透露。         |
| 训练轮数     | 至少5轮，最多10轮；第10轮 AI 回复完成后自动进入结束流程。      |
| 主动结束     | 用户可随时点击“结束训练”，至少完成1轮后允许评分。            |
| 中途退出     | 自动保存完整消息、当前轮数、患者情绪和已透露信息。           |
| 续练         | 用户再次进入时恢复历史对话和患者状态。                       |
| 加载状态     | 等待模型响应时显示“患者正在输入…”，禁止重复发送。            |

MVP 暂不展示情绪标签，不提供提示、快捷话术、标准答案、语音输入或实时评分，避免影响真实作答。

## 3.4 训练结果页
功能说明：训练结束后，由独立评分调用读取完整对话，生成结构化训练报告。

| **结果模块** | **展示内容**                                                     |
|--------------|------------------------------------------------------------------|
| 总分         | 0—100分，用于演示整体表现。                                      |
| 五维得分     | 情绪识别与同理心、口腔知识准确性、需求挖掘、服务礼仪、医疗合规。 |
| 综合评价     | 用简短文字概括本次表现。                                         |
| 优势         | 列出1—3项做得较好的行为。                                        |
| 改进建议     | 列出1—3项可直接执行的改进方向。                                  |
| 严重违规     | 如存在，展示用户原句、违规类型、原因、扣分和建议改写。           |
| 关键轮次点评 | 选择最有代表性的2—4个回合进行点评。                              |
| 推荐改写     | 针对关键问题提供更合规、清晰的表达示例。                         |
| 后续操作     | 重新训练、返回场景列表、查看历史记录。                           |

> **评分定位**  
> 自动评分由大模型根据固定评分量表生成，仅用于 MVP 演示和辅助反馈。文档与页面均不得宣称该评分可替代口腔医生、客服专家或正式培训考核。

## 3.5 历史记录页
功能说明：展示固定演示用户的训练记录，支持继续未完成训练和查看已完成报告。

| **记录字段** | **说明**                                                             |
|--------------|----------------------------------------------------------------------|
| 场景名称     | 本次训练所属场景。                                                   |
| 训练时间     | 开始时间及最后更新时间。                                             |
| 状态         | 进行中、已完成、已放弃。                                             |
| 轮数         | 当前已完成的用户发言轮数。                                           |
| 总分         | 仅已完成并评分的训练显示。                                           |
| 操作         | 进行中显示“继续训练”；已完成显示“查看报告”；所有记录可查看完整对话。 |

## 3.6 演示数据页
功能说明：替代原完整主管后台，仅用于现场展示系统对训练数据的汇总能力，不包含人员管理和权限。

| **指标**       | **计算方式**                               |
|----------------|--------------------------------------------|
| 总训练次数     | 全部会话数量，不含已放弃记录或可单独注明。 |
| 已完成次数     | 状态为已完成且存在评分报告的会话数量。     |
| 平均得分       | 全部已完成训练总分的算术平均值。           |
| 各场景训练次数 | 按4个场景分别统计。                        |
| 五维平均得分   | 按已完成训练聚合五个维度。                 |
| 最近训练       | 显示最近5条训练记录。                      |

不包含：成员列表、团队权限、任务发布、提醒、排行榜、薄弱项预警、报表导出和多门店。

# 4. 训练场景设计
每个场景均由“对用户可见信息”和“仅模型可见配置”两部分组成。可见信息帮助用户理解背景；隐藏信息用于检验用户是否会主动提问和识别风险。

## 4.1 种植牙基础咨询
| **配置项** | **内容**                                                             |
|------------|----------------------------------------------------------------------|
| 基础画像   | 52岁，缺失一颗后牙，对种植牙了解较少，初始情绪为平静但谨慎。         |
| 公开诉求   | 询问种植牙大致流程、是否疼痛以及需要多久。                           |
| 隐藏信息   | 存在预算压力；最担心手术疼痛；若客服只推价格而不询问需求，耐心下降。 |
| 训练重点   | 基础信息解释、需求挖掘、回应担忧、避免个体化诊断、引导专业检查。     |
| 良好结束   | 患者愿意进一步了解，并接受“需由医生检查后确定具体方案”的边界。       |
| 高风险行为 | 保证无痛、保证成功、直接判断患者适合种植、给出确定治疗周期。         |

## 4.2 正畸基础咨询
| **配置项** | **内容**                                                               |
|------------|------------------------------------------------------------------------|
| 基础画像   | 22岁，牙齿不整齐影响外观，对隐形矫正感兴趣，初始情绪为期待但犹豫。     |
| 公开诉求   | 询问正畸周期、费用以及是否需要拔牙。                                   |
| 隐藏信息   | 即将毕业，担心影响求职；预算有限；对“必须拔牙”非常敏感。               |
| 训练重点   | 澄清外观与功能诉求、说明检查流程、不直接判断是否拔牙、不承诺具体周期。 |
| 良好结束   | 患者理解需要面诊和影像检查，愿意考虑预约评估。                         |
| 高风险行为 | 直接认定需要/不需要拔牙，承诺固定疗程或绝对效果。                      |

## 4.3 与其他诊所比价
| **配置项** | **内容**                                                         |
|------------|------------------------------------------------------------------|
| 基础画像   | 45岁，已咨询多家诊所，认为当前报价较高，性格理性且警惕营销话术。 |
| 公开诉求   | 质疑价格，询问为什么比其他诊所贵。                               |
| 隐藏信息   | 并非只考虑最低价，更关心医生经验、材料、后续服务与收费透明度。   |
| 训练重点   | 先询问比较标准，解释价格构成，不贬低其他机构，不作绝对化承诺。   |
| 良好结束   | 患者愿意基于检查结果和具体方案继续比较，而非被强行促单。         |
| 高风险行为 | 攻击竞品、保证本机构最好、虚构材料或服务优势、隐瞒费用。         |

## 4.4 术后不适咨询
| **配置项** | **内容**                                                             |
|------------|----------------------------------------------------------------------|
| 基础画像   | 38岁，治疗后出现不适，情绪焦虑，担心治疗失败。                       |
| 公开诉求   | 描述疼痛或肿胀，希望客服判断是否正常。                               |
| 隐藏信息   | 症状时间、程度和伴随表现尚不完整；可能存在需及时联系医生的风险信号。 |
| 训练重点   | 先安抚、继续询问信息、识别风险、避免诊断、及时转接医生。             |
| 良好结束   | 患者获得明确的下一步行动建议，并理解客服不能替代医生判断。           |
| 高风险行为 | 未询问细节就说“肯定正常”、拖延就医、继续营销或给出治疗建议。         |

## 4.5 患者内部状态
为实现可控且可续练的基本情绪变化，每个会话至少保存以下内部状态。状态仅供后端和 Prompt使用，不直接展示给用户。

| **状态**             | **建议范围**                 | **作用**                               |
|----------------------|------------------------------|----------------------------------------|
| emotion              | 平静、犹豫、焦虑、不满、缓和 | 决定患者表达风格。                     |
| emotion_level        | -2至2                        | 表示情绪负向或正向程度。               |
| trust_level          | 0至100                       | 表示患者对客服的信任变化。             |
| revealed_information | 字符串数组                   | 记录已主动或被询问后透露的隐藏信息。   |
| risk_triggered       | true/false                   | 记录是否出现需优先转接医生的风险信号。 |
| current_round        | 0至10                        | 控制训练轮数和结束条件。               |

# 5. 用户流程
## 5.1 单次训练闭环
```text
[演示首页]
    ↓ 点击“开始训练”
[场景选择] → 查看公开患者画像与训练重点
    ↓ 选择场景
[创建会话] → AI 患者发送开场白
    ↓
[对练舱] ⇄ 用户文字回复 / AI 患者多轮回复
    ↓ 主动结束或达到第10轮
[自动评分] → 读取完整对话并生成结构化报告
    ↓
[训练结果] → 查看五维得分、违规说明、建议
    ↓
[历史记录] → 保存对话、评分与训练时间
```

## 5.2 中途退出与续练流程
```text
[对练中点击返回/退出]
    ↓
[自动保存] 消息 + 当前轮数 + 情绪 + 已透露信息
    ↓ 会话状态 = in_progress
[再次进入同一场景]
    ↓
“继续上次训练” / “重新开始”
├─ 继续：恢复历史上下文和患者状态
└─ 重开：旧会话标记 abandoned，创建新会话
```

## 5.3 训练结束条件
- 用户主动点击“结束训练”。

- 用户完成第10轮回复且 AI 返回本轮患者消息。

- 模型返回异常时不自动结束，页面提供重试；连续失败后允许保存并退出。

- 训练结束后会话不可继续发送消息，只能查看报告或重新训练。

## 5.4 现场演示推荐路径
为保证现场效果，建议准备两条固定演示路径：一条展示正常咨询和合理评分；另一条故意输入明显违规话术，展示系统识别原句、说明原因并大幅扣分。

# 6. 自动评分体系
## 6.1 评分原则
- 评分基于完整多轮对话，而不是只评价最后一句话。

- 严重医学错误和违规承诺必须明确指出原句、原因和扣分。

- 评分模型必须按固定 JSON格式返回，前端不直接解析自由文本。

- 评分结果强调可解释性，不以单一总分替代具体反馈。

- 由于暂无专家标注，评分只作为演示反馈，不宣称具有正式考核效力。

## 6.2 五维评分
| **维度**         | **权重** | **主要评价内容**                                   | **常见扣分点**                                 |
|------------------|----------|----------------------------------------------------|------------------------------------------------|
| 口腔知识准确性   | 25%      | 基础流程说明是否合理；是否避免错误知识和越权诊断   | 凭空确定方案、治疗周期或是否拔牙；错误解释风险 |
| 医疗合规         | 25%      | 是否避免疗效保证、风险隐瞒、不当营销和贬低其他机构 | “保证成功”“绝对无痛”“我们肯定最好”             |
| 情绪识别与同理心 | 20%      | 是否识别焦虑、犹豫或不满，并在给信息前作适当回应   | 忽略情绪、机械推销、指责患者                   |
| 需求挖掘         | 20%      | 是否询问主诉、顾虑、预算、时间和风险信息           | 未经询问直接推荐；术后场景未追问症状           |
| 服务礼仪         | 10%      | 表达是否礼貌、清晰、耐心，语气是否符合客服身份     | 语言生硬、过度口语化、打断或不耐烦             |

## 6.3 严重违规扣分
| **严重程度**          | **典型情况**                               | **建议扣分**            |
|-----------------------|--------------------------------------------|-------------------------|
| 一般问题              | 表达不够礼貌、追问不足、信息结构不清       | 5—10分                  |
| 明显不规范            | 替患者作较强判断、贬低其他机构、过度促销   | 10—20分                 |
| 严重医疗错误/违规承诺 | 保证疗效、错误处理风险症状、明确替医生诊断 | 30—50分                 |
| 重复严重问题          | 多次出现同类严重错误                       | 可累计扣分，总分最低为0 |

严重违规不设置固定一票否决，但必须显著影响总分，并在结果页单独显示。

## 6.4 评分输出结构
| **字段**         | **含义**                               |
|------------------|----------------------------------------|
| total_score      | 0—100整数。                            |
| dimension_scores | 五个维度各自0—100分。                  |
| summary          | 本次训练总体评价。                     |
| strengths        | 优势列表，每项包含对应轮次或证据。     |
| improvements     | 待改进项列表，给出可执行建议。         |
| violations       | 违规原句、类型、原因、扣分和建议改写。 |
| round_comments   | 关键轮次、用户原话、点评和更优表达。   |

## 6.5 评分一致性约束
- temperature 设置为低值，减少同一对话重复评分的波动。

- 固定评分 Prompt 版本，并将模型名称和 Prompt 版本写入评分记录。

- 总分应与五维加权结果基本一致；严重违规扣分单独列出。

- 若 JSON 解析失败，后端最多自动重试一次，仍失败则提示重新评分。

# 7. 模型能力与调用设计
## 7.1 总体方案
MVP 接入通用大模型 API，所有患者扮演和评分能力通过 Prompt 实现。业务上拆分为“患者模拟调用”和“自动评分调用”，即使底层暂时使用同一模型，也必须使用不同系统提示词、接口参数和输出结构。

```text
微信小程序
    ↓ HTTP API
Crow 业务后端
├─ PostgreSQL：场景、会话、消息、评分
└─ 模型网关
   ├─ 患者模拟 Prompt：逐轮调用
   └─ 自动评分 Prompt：训练结束后调用
```

## 7.2 患者模拟调用
患者模拟模型只负责扮演患者和更新内部状态，不评价用户表现，不输出教学建议，也不主动暴露系统提示词或全部隐藏信息。

| **输入**     | **内容**                                         |
|--------------|--------------------------------------------------|
| 场景配置     | 患者画像、公开诉求、隐藏信息、训练目标和风险点。 |
| 会话状态     | 当前情绪、信任度、已透露信息、轮数和风险标记。   |
| 历史对话     | 本会话全部消息或经后端裁剪后的有效上下文。       |
| 用户最新消息 | 本轮客服回复。                                   |

| **输出字段**               | **要求**                                      |
|----------------------------|-----------------------------------------------|
| reply                      | 患者本轮自然语言回复。                        |
| emotion                    | 当前情绪标签，供后端保存。                    |
| emotion_level              | -2至2整数。                                   |
| trust_level                | 0至100整数。                                  |
| newly_revealed_information | 本轮新透露的隐藏信息列表。                    |
| risk_triggered             | 是否触发需转接医生的风险。                    |
| should_end                 | 患者是否自然结束；MVP 仍以轮数和用户操作为主。 |

## 7.3 自动评分调用
评分模型在训练结束后一次性读取完整对话。Prompt 中必须包含场景目标、五维量表、严重违规规则、固定 JSON Schema 和“不得把建议写成医学诊断”的限制。

## 7.4 LoRA 接入预留
后端模型网关应避免将特定API 字段直接暴露给小程序。未来将 LoRA 模型部署为兼容的聊天接口后，只需替换模型网关的服务地址和模型名称；场景、会话、消息和评分接口保持不变。

| **阶段** | **模型来源**           | **主要用途**                                  |
|----------|------------------------|-----------------------------------------------|
| MVP 演示  | 通用大模型 API + Prompt | 快速完成患者模拟、自动评分和现场演示。        |
| 模型研究 | Qwen 基础模型 + LoRA    | 验证领域语料微调对口腔知识或表达风格的提升。  |
| 后续集成 | 部署后的 LoRA 模型服务   | 替换患者模拟或评分模型，并与 API 基线进行对比。 |

## 7.5 异常处理
- 模型调用超时：页面提示“回复生成失败”，保留用户消息并允许重试。

- 模型返回非 JSON：后端尝试修复或重试，不将原始异常内容展示给用户。

- 患者跳出角色：后端可追加纠偏 Prompt并重试一次。

- 敏感或无关输入：患者保持角色并引导回当前训练场景。

- 评分失败：会话仍标记为已结束但报告状态为待生成，允许再次请求评分。

# 8. 数据与状态设计
## 8.1 数据库选型
MVP 统一使用 PostgreSQL。后端采用 C++与 Crow框架时，数据库访问库统一使用 libpqxx，避免 MySQL与 libpqxx并存的技术冲突。

## 8.2 最小数据对象
| **对象**   | **主要内容**                                                  | **MVP 用途**                |
|------------|---------------------------------------------------------------|----------------------------|
| Scenario   | 场景名称、简介、画像、隐藏信息、训练目标、初始状态、最大轮数  | 驱动场景选择和患者Prompt。 |
| Session    | 固定测试用户、场景、状态、轮数、患者状态、开始/更新时间、总分 | 记录一次训练生命周期。     |
| Message    | 会话、角色、内容、轮次、发送时间                              | 保存完整多轮对话。         |
| Evaluation | 总分、五维得分、总结、优势、建议、违规、逐轮点评、模型版本    | 生成和回看训练报告。       |

## 8.3 会话状态
| **状态值**  | **含义**                         | **允许操作**                       |
|-------------|----------------------------------|------------------------------------|
| in_progress | 训练进行中或中途退出             | 继续训练、重新开始、查看当前对话。 |
| completed   | 对话已结束且已生成/正在生成评分  | 查看报告、重新训练。               |
| abandoned   | 用户选择重新开始，旧会话不再继续 | 仅查看记录，可在统计中排除。       |

## 8.4 数据保存范围
- 保存完整对话全文。

- 保存评分结果、违规说明、关键轮次点评和评分模型版本。

- 保存开始时间、结束时间、最后更新时间、场景和当前状态。

- 保存续练所需的患者情绪、信任度、已透露信息和当前轮数。

- 不保存真实姓名、手机号、诊疗记录、音频或微信用户身份。

## 8.5 核心接口范围
| **接口**                          | **用途**                           |
|-----------------------------------|------------------------------------|
| GET /api/scenarios                | 获取4个训练场景及公开信息。        |
| POST /api/sessions                | 创建新训练会话并返回 AI 患者开场白。 |
| GET /api/sessions/{id}            | 恢复会话、消息和内部状态。         |
| POST /api/sessions/{id}/messages  | 发送用户消息并获取 AI 患者回复。     |
| POST /api/sessions/{id}/finish    | 主动结束或自动结束训练并触发评分。 |
| GET /api/sessions                 | 获取历史训练记录。                 |
| GET /api/sessions/{id}/evaluation | 获取单次训练报告。                 |
| GET /api/dashboard                | 获取演示数据汇总。                 |

# 9. 非功能需求
## 9.1 性能体验
| **指标**   | **MVP 目标**                                            |
|------------|--------------------------------------------------------|
| 小程序首屏 | 普通网络环境下尽量在3秒内完成基础页面展示。            |
| AI 回复     | 发送后立即显示加载状态；单次模型调用建议在20秒内返回。 |
| 评分生成   | 训练结束后建议在30秒内生成报告。                       |
| 防重复提交 | 模型请求进行中禁用发送和结束按钮。                     |
| 历史加载   | 一次展示最近50条记录，MVP 可不做分页。                  |

## 9.2 安全与合规
- 页面明确标注“AI 模拟训练，不构成医疗建议”。

- 患者模型不得提供诊断、治疗建议或真实医疗服务。

- 评分建议不得要求客服替医生下结论。

- MVP 仅使用演示输入，不要求用户输入真实患者隐私。

- API 密钥只能存放在服务端环境变量中，不写入小程序代码。

- 日志避免打印完整API 密钥；错误日志可记录会话编号和异常类型。

## 9.3 可用性
- 页面结构保持简单，主流程不超过“首页—场景—对练—结果”四级。

- 对练页面清楚显示当前轮数和最大轮数。

- 中途退出前给出保存提示，避免用户误以为记录丢失。

- 所有失败操作提供明确重试入口。

- 不依赖语音、定位、相机或通讯录权限。

## 9.4 可扩展性
- 场景配置以数据库或 JSON形式保存，新增场景不修改核心对话流程。

- 评分维度和权重通过配置维护，后续可加入预约引导或异议处理。

- 模型调用统一经过后端网关，便于替换 API 模型或 LoRA 模型。

- 会话、消息和评分分表保存，为后续用户登录和主管端扩展预留基础。

# 10. MVP 范围与验收标准
## 10.1 P0功能范围
| **模块** | **必须完成**                                           |
|----------|--------------------------------------------------------|
| 首页     | 开始训练、历史记录、演示数据三个入口。                 |
| 场景     | 展示4个场景及公开画像。                                |
| 对练     | 文字多轮、上下文、轮数控制、主动结束、中途保存和续练。 |
| 评分     | 五维得分、总分、违规说明、优势、改进和关键轮次。       |
| 历史     | 查看状态、完整对话和训练报告。                         |
| 数据页   | 总次数、平均分、场景统计和五维平均分。                 |
| 后端     | Crow API、PostgreSQL 持久化、模型 API调用。              |

## 10.2 明确不做
- 微信授权登录、手机号登录和正式权限体系。

- 完整主管后台、团队成员管理、培训计划和消息推送。

- 语音输入、实时语音对话和语音情感分析。

- 提示、快捷话术、黄金话术、错题本、收藏和搜索。

- 打卡、积分、等级、徽章和排行榜。

- 行业基准、正式上岗判定、绩效评价和真实转化率分析。

- PDF/Excel 导出、多门店、多团队和复杂数据权限。

- MVP 内在线部署 LoRA 模型；当前仅预留模型接口。

## 10.3 功能验收标准
| **验收项** | **通过条件**                                                       |
|------------|--------------------------------------------------------------------|
| 场景展示   | 可以看到并进入4个指定场景。                                        |
| AI 患者     | 任一场景能够维持患者身份完成至少5轮对话。                          |
| 上下文     | AI 患者能够引用前文至少一项信息或用户承诺。                         |
| 轮数控制   | 用户可主动结束；达到10轮后系统自动结束。                           |
| 续练       | 中途退出后能够恢复对话和轮数。                                     |
| 自动评分   | 结束后返回五维分数、总分、总结和建议。                             |
| 违规识别   | 输入明显保证疗效或越权诊断语句时，报告能指出原句和原因并大幅扣分。 |
| 历史记录   | 可以查看训练时间、状态、完整对话和报告。                           |
| 演示数据   | 完成训练后统计数据能够同步更新。                                   |
| 数据库     | 会话、消息和评分在服务重启后仍可读取。                             |

## 10.4 现场演示用例
| **用例** | **操作**                                         | **期望展示**                                                     |
|----------|--------------------------------------------------|------------------------------------------------------------------|
| 正常咨询 | 在种植牙场景中先询问顾虑，再说明需检查后确定方案 | 患者情绪逐步缓和，评分中同理心、需求挖掘和合规较高。             |
| 越权判断 | 在正畸场景中输入“你这个肯定不用拔牙”             | 报告识别越权判断，说明需由医生检查后决定，并明显扣分。           |
| 不当比价 | 在比价场景中贬低其他机构                         | 报告识别不当竞争表达，给出更中性的费用说明方式。                 |
| 术后风险 | 先询问疼痛时间和严重程度，再建议联系医生         | 报告肯定风险识别和转接意识；若直接说“肯定正常”则识别为严重问题。 |

## 10.5 一天开发优先顺序
1.  固定4个场景数据与患者Prompt。

2.  完成场景选择、对练和消息持久化。

3.  完成结束训练与评分 Prompt。

4.  完成结果页和历史记录。

5.  完成演示数据页。

6.  最后补充续练、异常提示和界面细节。

- 保留模型名称、版本和 Prompt 版本，支持追踪不同模型生成的报告。

| **阶段** | **可扩展内容**                                             |
|----------|------------------------------------------------------------|
| P1       | 错题复练、能力趋势、话术锦囊、更多场景、简单测试用户切换。 |

## 11.3 专业性补强
若产品进入真实试用阶段，必须引入口腔医生或有经验的客服培训人员，审核场景、标准表达、风险规则和评分量表，并用人工评分数据验证模型评分的一致性。

## 11.4 角色互换患者模拟（已实现）

在既有四个场景上新增独立的“患者模拟”模式：学员扮演患者，向标准口腔客服连续提问，单次最多 10 轮。场景页提供公开的建议提问；每轮标准客服答复默认展开 2—4 条学习要点和必要的合规边界，帮助新人理解答复的组织方式。

该模式不对学员进行五维评分，也不进入客服训练的数据看板。结束后仅生成整体接待总结、已覆盖问题、关键服务原则和后续练习建议；历史页按“客服训练 / 患者模拟”分开筛选、续练和回看。数据独立保存为 `roleplay_sessions`、`roleplay_messages`、`roleplay_summaries`，避免影响既有评分和统计。

标准客服 Prompt 与复盘 Prompt 均执行既有医疗安全边界：不诊断、不承诺疗效/疼痛/安全性、不编造价格或疗程，涉及诊疗判断时引导由医生结合检查评估。模型异常时保留患者问题并支持同一 `clientMessageId` 重试。
